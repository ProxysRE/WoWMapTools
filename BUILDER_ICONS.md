# WoW-иконки в готовых документах Foundry

Пакетный Builder теперь выбирает иконки из приватной выгрузки, проверяет исходные
байты, конвертирует выбранные изображения в **WebP без потерь** и назначает пути в
готовых JSON. Поддерживаются отдельные документы, вложенные предметы/способности
NPC, эффекты с полем `img` и явно выбранное изображение прототипа токена.
Канонические исходники Builder и игровые механики при этом не меняются.

Выбор делается ассистентом по каталогу: программа не угадывает соответствие
между русским названием предмета и файлом клиента. Внутри нет языкового ИИ.
Неизвестное или неоднозначное имя останавливает сборку.

Название файла — только способ поиска. Перед выбором ассистент просматривает сами
картинки: например, `inv_stone_01` изображает алмаз, а не камень для метания.
Автоматической проверки смысла изображения в программе нет.

## Локальное расположение ресурсов

В папке иконок должны находиться `catalog.jsonl.gz` и ZIP-пакеты из выгрузки.
Поддерживается исходная подпапка `packages/` и плоская раскладка ZIP рядом с каталогом,
как в загруженном на Drive наборе. Укажите эту папку через `--icon-assets`.
Исходный клиент, MPQ и StormLib для сборки с готовой выгрузкой не нужны.

Поиск по английским фрагментам имени файла:

```console
python -m wowmap.icons --assets "D:\WoWAssets\Icons" --query "inv_misc_key"
python -m wowmap.icons --assets "D:\WoWAssets\Icons" --query "spell fire" --limit 20
python -m wowmap.icons --assets "D:\WoWAssets\Icons" --query "inv_stone" --limit 50 --preview-dir output/icon-candidates
```

Результат содержит пути и общее число совпадений. Для сборки выбирается **точное**
имя без расширения (`inv_misc_key_01`), имя с расширением или полный виртуальный путь.
Пути и имена сравниваются без учёта регистра. Готовые изображения сохраняются в
исходном разрешении: детализация сверх оригинала не придумывается.
`--preview-dir` создаёт листы `icon-review-001.png` и далее, по 24 картинки на лист,
с именами файлов для визуального выбора. Увеличение значков в листе проверки
не изменяет экспортируемые WebP.

## Задание Builder

Поле `icons` добавляется к конкретному документу пакетного задания:

```json
{
  "id": "marta",
  "mode": "npc",
  "source": "requests/builder/sources/marta.json",
  "icons": {
    "/items/0/img": "inv_misc_key_01"
  }
}
```

Ключ — JSON Pointer к изображению **в готовом документе**, после обработки настоящим
Builder. `/img` задаёт основной значок, `/items/0/img` — значок первого вложенного
предмета, `/prototypeToken/texture/src` — изображение прототипа токена.
Допускаются только поля `img` и `texture/src`; названия, характеристики, урон и
прочую игровую механику через эти привязки изменить нельзя.
Промежуточные объекты и индексы списка должны существовать. Значение `img` может
быть добавлено, если у существующего объекта его ещё не было.

Для вложенных предметов NPC предпочтительнее `item_icons`: ключом служит точный
`system.identifier` готового предмета, а не его индекс в массиве:

```json
"item_icons": {
  "brum-stone": "inv_stone_16",
  "brum-hearing": "ability_vehicle_sonicshockwave"
}
```

Это поле находится рядом с `icons` в записи документа. Перестановка предметов
не меняет назначение значков. Отсутствующий или повторный идентификатор останавливает
сборку. Если `icons` и `item_icons` назначают одну картинку одного предмета,
сборка также останавливается, даже когда выбраны одинаковые файлы.

Пример уже находится в `requests/builder/icons-demo.json`:

```console
python tools/build_foundry_batch.py requests/builder/icons-demo.json --icon-assets "D:\WoWAssets\Icons" --out output/icons-demo
```

Собираются прежние два NPC, ключ и заговор. WoW-иконка ключа назначается и отдельному
предмету, и ключу в инвентаре Марты; огненный значок — демонстрационному заговору.
Портреты NPC остаются прежними: это не генератор обликов персонажей.
Наборы `enhancement_set`, содержащие отдельный модуль, пока не поддерживают такие
привязки; попытка завершается явной ошибкой. Для обычных JSON режимов ограничения нет.

## Что получает мастер

В результате находятся готовые JSON, отчёты, `population.json` для дальнейшей сборки
карты и папка `wowmap/content/icons/` с выбранными изображениями. В `build-report.json`
перечислены источники и SHA-256 файлов. Одна иконка не копируется отдельно для каждого
предмета: имя готового WebP строится по хешу его содержимого.
Для заданных привязок создаются `icon-bindings.json` и листы `icon-review-*.png`:
на них рядом видны документ, название способности и исходный значок. Листы нужны
для просмотра перед выдачей пакета; они не подтверждают соответствие автоматически.
Эти файлы лежат рядом с JSON и не копируются в Data.

1. Скопируйте **папку `wowmap` целиком** в пользовательскую папку **Data сервера Foundry**,
   туда же, где уже лежит `wowmap` с картами. Объедините папки, сохранив прежние карты.
2. Импортируйте нужные файлы актёров/предметов/заклинаний через обычный импорт JSON.
3. `population.json`, `build-report.json` и `*.report.json` не импортируются как листы.

Общие иконки лежат отдельно от конкретной карты: при смене папки карты их пути
остаются `wowmap/content/icons/...`. При переносе мира на другой сервер перенесите
также эту папку. JSON содержит ссылки, а не встроенные байты картинки.

## Карта сразу с населением

Прежняя команда присоединения `wowmap.population` теперь автоматически переносит
иконки из результата Builder в экспорт карты. Перед изменением JSON она проверяет
наличие картинок, контрольные суммы и конфликты файлов. Импортёр проверяет также
изображения вложенных предметов/способностей NPC до создания актёров и сцен.
Это покрыто автоматическими проверками; игровой тест в Foundry требуется отдельно.

## GitHub и приватные ресурсы

Код, задания и проверки находятся в ветке `foundry-builder`. Графика WoW в публичный
репозиторий не добавляется. Тесты Actions используют искусственные изображения.
Обычный размещённый GitHub runner не получает доступа к приватному Google Drive
из нашего чата: задания с `icons` требуют предоставить каталог и ZIP в среду сборки
через `--icon-assets`. Пока ассистент может получить их через подключённый Drive и
собрать готовый пакет в рабочем окружении; локальная команда выше работает так же.
Задания без привязок иконок продолжают собираться существующим workflow как раньше.
Графический интерфейс самостоятельного Builder 1.5 не менялся: эта интеграция
находится в пакетном инструменте ассистента.


## Проверки выпуска 30.10.2026

Пакетный адаптер повторно использует открытый ZIP иконок до конца сессии. Каждый новый значок по-прежнему сверяется по размеру и SHA256. Отдельная иконка эффекта также должна быть выбрана из подтверждённых файлов; пустые и стандартные изображения наследуют иконку предмета.
