# Нативный экспорт сцен Foundry 13

Цель: **Foundry VTT 13, сборка 351**. Документация API ветки v13 обозначена 13.350; совместимость с установленной 13.351 дополнительно проверяет импортёр. Возможности v14, в частности новая модель уровней сцен, сюда не переносятся автоматически.

## Какие механики существуют и что с ними делает программа

| Механика Foundry 13 | Поддержка |
|---|---|
| Масштаб, квадратная сетка, единицы расстояния | Экспортируются. На картинке сетки нет. |
| Стены: движение, зрение, свет, звук | Экспортируются отдельно, включая направление и пороговые ограничения. |
| Обычные и тайные двери, открыто/закрыто/заперто | Экспортируются из проёмов. Дверные значки штатные. |
| Окна, арки, невидимые и проходимые барьеры | Окна по умолчанию блокируют движение и пропускают зрение/свет. Арки не создают препятствий. Другие варианты задаются явно. |
| Свет: яркий/тусклый радиус, цвет, угол, анимация | Экспортируется. Тени и видимость рассчитывает Foundry. Зрение токена не создаётся автоматически источником света. |
| Общая темнота, глобальный свет, исследование тумана | Настройки сцены экспортируются. Персональное зрение задаётся персонажам в Foundry. |
| Тайлы, крыши/кроны, высота и скрытие при перекрытии | Верхний слой становится tile; внешние тайлы можно задать явно. Сейчас кроны — один общий tile, способный скрываться целиком. Отдельные крыши можно добавить отдельными тайлами. |
| Лестницы и переходы | Зоны с `teleportToken`, в пределах сцены или между сценами/этажами. Геометрия лестницы сама по себе переход не создаёт: нужны зоны входа/назначения. |
| Зоны: подавление погоды, пауза игры | Поддержаны штатные поведения `suppressWeather`, `pauseGame`. |
| Зоны: стоимость движения, локальная темнота | Экспорт явных `system`-данных штатных `modifyMovementCost`, `adjustDarknessLevel`; проверка схемой при импорте. Упрощённый независимый от системы формат ещё не сделан. |
| Дождь/снег и окружающие звуки | Можно задавать тип погоды и позиционные звуки. Аудиофайлы должны уже находиться в Data; программа их не извлекает и не включает автоматически. |
| Зоны: текст, макросы, скрипты, переключение поведений | В ядре есть; автоматическая генерация пока не реализована. |
| Заметки журнала, рисунки, измеряемые шаблоны | В ядре есть; текущий экспорт их не создаёт. |
| Токены, инициатива, урон ловушек, спасброски, условия | Зависит от правил и системы. [Builder и население](BUILDER_GITHUB.md) добавляют актёров и токены. Инициатива, ловушки и условия не выводятся автоматически из рисунка карты. |
| Полноценные этажи поверх друг друга с независимыми стенами | Не поддержаны этим экспортом. Для v13 нужны отдельные сцены (реализовано) либо отдельная интеграция с модулями уровней/высоты стен. Число elevation само по себе не превращает плоские стены в 3D. |

## Как импортировать готовый комплект

1. Распакуйте экспорт. Папку **`wowmap`** скопируйте в **Data сервера Foundry**, сохранив вложенные каталоги. Это Data пользовательских данных, не каталог установки программы. На хостинге используйте файловый менеджер хостинга.
2. В Foundry создайте макрос типа **Script**, вставьте текст **`import-foundry.js`**, запустите от мастера.
3. Путь к `bundle.json` уже указан. Если загрузили папку в другое место, измените путь в окне. Импортёр заменит пути к собственным изображениям.
4. Откройте созданную сцену. Стены, свет и переходы находятся в штатных слоях Foundry и редактируются обычными средствами.

Импортёр проверяет версию, конфликт ID, схему установленного Foundry и наличие файлов перед созданием. Существующие сцены не меняются. Повторный импорт того же комплекта останавливается; для независимой копии экспортируйте с новым `--id`. Если сервер прервёт создание, могут остаться частично созданные новые сцены — автоматического удаления нет.

Этажи импортируйте **вместе через макрос**, который сохраняет ID сцен и вложенных зон. Импорт отдельных `scene.json` через стандартный диалог подходит для автономной сцены, но может изменить ID и нарушить межсценовые переходы. Файлы изображений в JSON не встроены.

Для телепортации в другую сцену игроку нужны права `TOKEN_CREATE` и `TOKEN_DELETE`, владение токеном. По умолчанию `choice: true` предлагает игроку подтвердить переход. Возврат — отдельное поведение обратной зоны. Боевой и пользовательский сценарий перехода надо проверить в вашей игре.

Фон `map-vtt.webp` отличается от обычного `map.webp`: на нём нет крон верхнего слоя и дверных полотен. Кроны экспортируются отдельно, двери управляются значками Foundry. Анимированного текстурного полотна двери пока нет; закрытая дверь всё равно блокирует движение/видимость согласно настройкам.

## Создание экспорта у себя

[Установите текущую программу](INSTALLATION.md) и отрисуйте планы. Экспорту нужен `map-vtt.webp`; если его нет в старом рендере, перерисуйте план. Ресурсы WoW переэкспортировать не нужно.

- `render_scene.bat` — выбираете план и ZIP-ресурсы.
- `export_foundry.bat` — выбираете каталоги отрисованных сцен (можно несколько этажей), ID комплекта и родительский каталог экспорта.

Или:

```console
python -m wowmap render examples/foundry-tavern-ground.json --packages D:\WoWAssets --out output/inn-ground
python -m wowmap render examples/foundry-tavern-upper.json --packages D:\WoWAssets --out output/inn-upper
python -m wowmap.foundry --scene output/inn-ground --scene output/inn-upper --id my-inn --out output/foundry-my-inn
```

Каталог назначения должен отсутствовать или быть пустым. Минимальный размер клетки Foundry — 50 px: планы с меньшим разрешением нужно перерисовать с подходящим масштабом. Изображения упаковываются в WebP без потерь.

## Формат плана

Все поля необязательного блока `foundry` относятся только к механикам VTT. Позиции/размеры и радиусы света/звука — **клетки**. Высоты и пороги стен — **единицы сцены**, например футы; они не умножаются на pixels_per_cell. При экспорте радиусы пересчитываются в distance_per_cell.

```json
{
  "foundry": {
    "key": "ground",
    "darkness": 0.65,
    "global_light": false,
    "grid_alpha": 0.2,
    "lights": [
      {"id":"fire", "position":[10,8], "bright":3, "dim":6,
       "color":"#ffb568", "alpha":0.4,
       "animation":{"type":"torch", "speed":3, "intensity":3}}
    ],
    "regions": [
      {"id":"stairs-up", "name":"Наверх",
       "shapes":[{"type":"rectangle", "bounds":[17,7,19,9]}],
       "behaviors":[{"type":"teleportToken", "choice":true,
                     "destination":{"scene":"upper", "region":"stairs-down"}}]}
    ]
  }
}
```

`key` уникален в комплекте, только `a-z`, `0-9`, дефис. Если не задан, используется имя каталога рендера. Ссылки назначения проверяются до записи файлов. Стабильные 16-символьные ID выводятся из ID комплекта, ключа сцены и ID элемента.

Формы зон: rectangle/ellipse с bounds или polygon с points; cutouts создают holes. У зон нет размытия/нерегулярных краёв, пути нужно описать полигоном. Неограниченная высота по умолчанию, либо `elevation: {"bottom":0,"top":10}`. Это фильтр зоны, не этажная система стен.

У стены/двери/окна можно задать блок `foundry` с `move` (`normal/none`), `sight/light/sound` (`none/limited/normal/proximity/distance`), `direction` (`both/left/right`), `threshold`. Дверь дополнительно принимает `secret:true`. Для proximity/distance соответствующий порог обязателен. Политика окна в DEV0.5 — прозрачное окно; вариант видимости только вблизи задаётся через proximity и threshold явно.

`foundry.barriers`: `id`, `points`, `closed`, те же параметры ограничений. Нужны, например, для невидимой границы обрыва или ствола дерева. Физические ограничения моделей не угадываются по силуэту.

`foundry.sounds`: `id`, `position`, `path`, `radius`, `volume`. `path` — существующий путь относительно Data. `foundry.tiles`: `id`, `position` (левый верх), `size_cells`, `path`, `elevation`, `overhead`, `blocks_light`. Файлы внешних тайлов и звуков перечисляются в `externalMedia` и проверяются импортёром, но в комплект автоматически не копируются.

Из поведения зон поддержаны `teleportToken` с destination/choice, `pauseGame` с once, `suppressWeather`. Продвинутые `modifyMovementCost` и `adjustDarknessLevel` принимают нативный объект `system`; его структуру необходимо брать из v13/установленной игровой системы, а не из v14. Неизвестные типы поведения вызывают ошибку.

## Проверки и границы результата

Проверки Python покрывают разрезание стен проёмами, состояния/тайные двери, координаты, единицы света, связи этажей, вырезы зон, устаревшие планы и упаковку. JavaScript проверяется с имитацией API: отсутствие изменений при ошибке схемы/файлов/конфликте, сохранение ID, перенос путей. Это **не запуск настоящего Foundry**.

Пользователь подтвердил работу импорта DEV0.5 в своей Foundry 13.351 с системой dnd5e 5.3.3: стены, двери и переходы между этажами работают. Отдельно ещё стоит оценить видимость через окна, блокирование света и верхний слой. Новый вариант «Старый дуб» DEV0.6 использует тот же экспортёр, с дневными настройками света.

## Видео-тайлы поверх статичной карты

У `foundry.tiles` можно явно задать `opacity` (0..1) и
`video: {"autoplay": true, "loop": true, "volume": 0}`. `path` указывает
на локальный WebM, который должен находиться в Data и включаться в поставку.
Конвертировать всю карту в видео не требуется. Полные M2-частицы этим не
воспроизводятся; см. [эффекты окружения](ENVIRONMENT_FX.md).
