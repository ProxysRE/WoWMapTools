# SPECIFICATION_0.1 — WoWMapTools

## Принятые решения

- Ассистент проектирует сцены и выбирает ресурсы; программа выполняет точные задания.
- Основной результат — ортографическая боевая карта и в дальнейшем сцена Foundry.
- Стартовый клиент: WoW WotLK 3.3.5a. Путь к клиенту задаётся локально и не публикуется.
- Целевая Foundry: 13, build 351. Полный экспорт требует проверки непосредственно в этой версии.
- Здания разрешено собирать из текстур пола и стен. Префабы WMO необязательны.
- Ресурсы остаются локальными. Репозиторий содержит программу, планы и документацию.
- Не требуется встроенный языковой ИИ. Случайность вспомогательная и воспроизводимая.

## DEV0.1: реализованная часть

Импорт PNG ZIP → каталог → JSON-план → рендер поверхности.

Формат `wowmap.scene/1`:

| Поле | Значение |
|---|---|
| `format` | `wowmap.scene/1` |
| `name` | Название сцены |
| `seed` | Целое число |
| `size_cells` | Ширина и высота в клетках |
| `pixels_per_cell` | Масштаб рендера |
| `distance_per_cell`, `units` | Игровой масштаб, по умолчанию 5 ft |
| `base` | Сплошное покрытие |
| `layers` | Наложения в порядке от нижнего к верхнему |
| `surface_variation` | Слабая вариация яркости 0…0.3, не источник света |

Координаты: начало в левом верхнем углу, X вправо, Y вниз. Все геометрические параметры — в клетках, перевод в пиксели только в рендере/экспорте.

Слой: уникальный `id`, `asset` (исходный полный путь либо `png:<sha256>`), `tile_cells` (ширина повтора текстуры в клетках), `opacity` 0…1.

Формы:

- `ellipse`: `bounds: [x0,y0,x1,y1]`.
- `polygon`: `points: [[x,y], ...]`.
- `path`: `points` и `width`; ломаная с круглыми стыками.
- Для всех: `feather` — радиус размытия маски в клетках; `roughness` — сила нерегулярности перехода.

PNG-каталог содержит категорию `terrain`, `model_texture` или `worldmap`. Категория выводится из пути, а не из анализа картинки. `_s` отмечается как вспомогательная текстура без предположений о её точной роли. Текстуры моделей не являются готовыми объектами с видом сверху.

Ограничение рендера: 20 млн пикселей. Импорт ZIP: максимум 512 MiB PNG в распакованном виде. Опасные пути отклоняются до записи ресурсов. Каталог объединяется при повторном импорте.

## Дальнейшие этапы

### DEV0.2 — автоматический доступ к клиенту

- Прямое чтение MPQ без изменения архивов; поиск имён и диагностика неполных listfile.
- Явный порядок приоритета архивов и патчей; обнаружение нескольких вариантов файла.
- Экспорт BLP по идентификаторам из задания и кэширование преобразований.
- Каталог, доступный ассистенту: метаданные и запрашиваемые листы превью.
- Совместимость задач с локальным исполнителем из DEV0.1.

### DEV0.3 — объекты

- Подготовка M2/WMO, материалов и зависимостей; ортографические превью.
- Кэш готовых объектов сверху, размер в клетках, точка привязки, поворот.
- Стволы отдельно от крон для игрового поведения.
- Первый законченный лагерь: деревья, камни, палатки, костёр, предметы.

### DEV0.4 — строения и Foundry 13

- Модульные полы, стены, проёмы и шаблоны игровой геометрии.
- Двери и окна — отдельные элементы; запреты движения и обзора задаются явно.
- Источники света: координаты, цвет, яркая/тусклая зоны, параметры анимации.
- Визуальный свет и динамический свет экспортируются раздельно.
- Изображение плюс JSON сцены Foundry; далее дополнительный Universal VTT экспорт.
- Проверка совпадения масштаба, координат, дверей и видимости в Foundry 13.351.

## Проверено для DEV0.1

- Пользовательский PNG.zip: 110 корректных PNG; 26 покрытий (включая вспомогательные), 50 текстур моделей, 34 фрагмента карты региона.
- Локальный рендер примера 3200×2400 из оригинальных текстур.
- Повтор одного плана даёт одинаковый PNG в одной среде; смена seed изменяет результат.
- Между версиями Pillow/NumPy байтовая идентичность не гарантируется.
- Windows BAT и GitHub workflows подготовлены; запуск на пользовательском ПК требует отдельной проверки.
