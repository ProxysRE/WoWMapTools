# Установка и расположение файлов

Общая инструкция для всех инструментов. Профильные руководства описывают
свои параметры и результат.

## Получение программы

Используйте ветку **foundry-builder**, если нужны карты вместе с Builder,
иконками и токенами. Для уже подготовленных ZIP достаточно исходников этой ветки:
**Code → Download ZIP** или git checkout.

Для извлечения MPQ нужна Windows x64-сборка с DLL:

1. Откройте **Actions → Windows packer**, последний успешный запуск нужной ветки.
2. Скачайте **WoWMapTools-DEV0.6.2-Windows**. Имя артефакта не отражает каждую правку;
   ориентируйтесь на ветку и коммит запуска.
3. Распакуйте артефакт, затем ZIP программы внутри него.

В сборке находятся `tools/StormLib.dll` и лицензия StormLib.
Исходный ZIP DLL не содержит. Для чтения ресурсных ZIP и рендера StormLib не нужна.

## Настройка

На Windows нужен **Python 3.10+**, для MPQ — **64-bit**, с `py` launcher.
Запустите `setup_windows.bat`: создаётся `.venv` и устанавливается
`requirements.txt`. В CLI используйте `.venv\Scripts\python.exe` вместо
`python`, если окружение не активировано. BAT сами переходят в папку программы.

| Операция | Запуск |
|---|---|
| Выгрузка графики / значков / таблиц | `pack_for_drive.bat` / `pack_icons.bat` / `pack_dbc.bat` |
| Рендер JSON-плана | `render_scene.bat` |
| Экспорт отрисованных этажей | `export_foundry.bat` |
| Графический Builder | `foundry_builder/start_builder_app.bat` |
| Пакетная сборка | [BUILDER_GITHUB.md](BUILDER_GITHUB.md) |

На Linux создайте venv и установите `requirements.txt`. Для MPQ нужна подходящая
StormLib; `WOWMAP_STORMLIB` задаёт её путь. Команды сборки зависимости находятся в
[workflow](.github/workflows/packer.yml), включая Linux-проверку.

## Каталоги

| Каталог | Назначение |
|---|---|
| **Data клиента WoW** | MPQ. Выбирается при извлечении; клиент не изменяется. |
| **Папки выгрузок** | Оригиналы и каталоги. Отдельные наборы графики, иконок и DBC для сборки. |
| **Пользовательская Data сервера Foundry** | Миры, системы, игровые изображения. Сюда копируется только `wowmap` готового комплекта. |

Data Foundry — не каталог установки и не Data клиента WoW. Путь задаётся настройками
сервера; на хостинге используйте файловый менеджер. JSON и отчёты храните отдельно:
`wowmap` объединяйте с существующей, документы импортируйте по инструкции комплекта.

Сохраняйте три независимые выгрузки: графику, иконки, DBC. Их `summary.json` и
`catalog.jsonl.gz` имеют одинаковые имена, но разное содержимое. Не заменяйте один
набор другим. Поддерживаются ZIP в корне набора и в `packages/`.
Распакованные M2 вместо ZIP не являются входом `--model-assets`.

PNG из wow.export — отдельный старый вход: `import_png.bat` создаёт
`assets/catalog.json` и `assets/files`. Он поддерживается, но для BLP/ZIP
повторный PNG-экспорт не нужен.

## Обновление

Обновите исходники выбранной ветки. При новой установке выполните
`setup_windows.bat`; при обновлении существующей сохраните свои ресурсы,
`assets`, `output` и DLL. После изменения зависимостей повторите установку.
Не переносите старую `.venv` в другой путь.

Обновление программы не меняет NPC и сцены в Foundry. Новая сборка создаёт файлы;
старые размещённые токены автоматически не обновляются. Для пакетной сборки и
экспорта используйте отсутствующий или пустой каталог назначения.
Рендер может переиспользовать свой каталог; это не способ обновления мира Foundry.
