# WoWMapTools — DEV0.4

Инструмент создания боевых карт из локальных ресурсов WoW. Ассистент составляет точный план сцены в JSON; программа воспроизводимо рисует его. Встроенного ИИ и платных API нет.

**DEV0.4 — общий конструктор сцен:** местность, текстурные полы, стены с проёмами, мебель, дороги, вода и управляемая расстановка окружения. Лагерь — один из примеров.

Сетка в изображения не добавляется. Для Foundry сохраняется только масштаб в данных. Новые примеры используют WebP без потерь.

Запустите `setup_windows.bat`, затем **`render_scene.bat`**: выберите любой JSON сцены и папку ZIP-ресурсов. Можно перетащить JSON на BAT. StormLib.dll для рендера готовых пакетов не требуется.

[Формат общего плана и возможности](SPECIFICATION_0.4.md) · [Расстановка моделей](SPECIFICATION_0.3.md) · [Технические ограничения M2](MODEL_PREVIEWS.md) · [Упаковщик для Drive](PACK_FOR_DRIVE.md).

Запрос мастера интерпретирует ассистент: он составляет план и проверяет сцену. Внутри программы нет языкового ИИ. Возможности расширяются новыми примитивами по мере появления задач.

## Что работает

- **DEV0.4:** полы, стены, двери, окна, плавные пути, вырезы покрытия, ограниченная расстановка и поиск ресурсов.
- **DEV0.3:** 44 объекта в примере лагеря; масштаб, поворот, точка привязки, перекрытие, тени, кэш и отдельный верхний слой деревьев.

- **DEV0.2:** чтение MPQ, отбор графики, приоритет стандартных патчей, самостоятельные ZIP-пакеты, каталог, превью и продолжение после прерывания.
- Проверка нативного чтения сжатого MPQ и сборка Windows DLL в отдельном workflow `Windows packer`.

- Импорт ZIP с PNG из wow.export, классификация ресурсов и постоянные SHA-256 ID.
- Повторный импорт без дублирования записей; исходные пути сохраняются в каталоге.
- Поиск по каталогу и создание листа превью покрытий.
- Слои местности: эллипсы, многоугольники, тропы; мягкие и нерегулярные границы.
- Масштаб текстур, прозрачность слоёв, фиксированный seed.
- PNG или WebP без сетки, JPEG-превью и параметры рендера.
- Пример Ясеневого леса 40×30 клеток, 80 пикселей на клетку (3200×2400).
- Проверки в GitHub Actions на Windows и Linux с искусственными тестовыми текстурами.
- Шаблон запуска на локальном Windows runner через GitHub — выключен до настройки.

**Пока отсутствуют:** полноценный рендер моделей WoW и поддержка WMO, автоматическое получение зависимостей моделей, динамический свет и нативный экспорт сцены Foundry. Текстурные здания и структурные стены/двери/окна реализованы в DEV0.4. Прямое чтение стандартных MPQ реализовано в отдельном упаковщике. Эти функции описаны в [SPECIFICATION_0.1.md](SPECIFICATION_0.1.md). Целевая версия Foundry — 13, сборка 351.

## Быстрый запуск на Windows

Нужен Python 3.10 или новее с установленным `py` launcher. Python и зависимости скачиваются один раз при настройке.

1. Скачайте репозиторий: **Code → Download ZIP**, распакуйте, например в `D:\WoWMapTools\App`.
2. Запустите `setup_windows.bat`. Он создаст отдельное окружение `.venv` и установит Pillow и NumPy.
3. Перетащите ранее полученный `PNG.zip` из wow.export на `import_png.bat`. Исходный ZIP не изменяется. Не нужно экспортировать текстуры заново.
4. Запустите `render_example.bat`.
5. Результат появится в `output\ashenvale`; превью откроется автоматически.

Ресурсы сохраняются в `assets\files`, каталог — `assets\catalog.json`. Эти папки исключены из git. Импорт PNG и рендер не обращаются к клиенту. Упаковщик читает MPQ без изменения архивов.

Для примера нужен экспорт с исходными путями вида `common.MPQ/tileset/ashenvale/ashenvaledirt.png` — именно такая структура у первого пользовательского PNG.zip. Отсутствующие ресурсы вызывают понятную ошибку, а не заменяются вымышленными текстурами.

## Командная строка

После установки используйте `.venv\Scripts\python.exe` вместо `python`, если окружение не активировано.

```console
python -m wowmap import-png "D:\Exports\PNG.zip" --assets assets
python -m wowmap catalog --assets assets --filter ashenvale
python -m wowmap gallery --assets assets --out output/catalog.jpg
python -m wowmap validate examples/ashenvale-camp.json --assets assets
python -m wowmap render examples/ashenvale-camp.json --assets assets --out output/ashenvale
python -m unittest discover -s tests -v
```

Измените `seed`, чтобы поменять нерегулярность переходов и смещения текстур. **Планировка остаётся заданной JSON**: для другой сцены ассистент меняет её формы и координаты. Seed не придумывает новую композицию.

## Результат

| Файл | Содержание |
|---|---|
| `map.png` | Фон карты без сетки |
| `preview.jpg` | Уменьшенное изображение |
| `scene-plan.json` | Точное задание для повторного рендера |
| `render.json` | Размеры, масштаб, seed и хеш плана |

`render.json` **не является сценой Foundry**. Фон загружается вручную; масштаб берётся из данных конкретной сцены (новые примеры: 72 px и 5 ft). Структурная геометрия записывается отдельно для будущего экспорта, но интерактивных стен и света Foundry пока нет.

## Автоматический запуск через GitHub

См. [RUNNER_SETUP.md](RUNNER_SETUP.md). Файл задания — `requests/active.json`. После настройки исполнителя изменения этого файла в `main` запускают рендер на вашем ПК, результаты возвращаются как артефакт `wowmap-render`.

Сам исполнитель пока не установлен. GitHub не получает доступ к диску D: автоматически. До настройки workflow пропускает задание.

Исходные изображения и клиент WoW не включены в репозиторий. Для запуска нужен собственный локальный набор ресурсов.
