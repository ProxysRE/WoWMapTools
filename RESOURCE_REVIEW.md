# Ресурсы, читаемость предметов и лестницы

Перед повторным размещением предмета проверяются **две разные вещи**:
комплектность ресурсов и внешний вид при конечном масштабе карты.
Видимые полигоны сами по себе не доказывают, что предмет узнаваем.

## Диагностика зависимостей

```console
python -m wowmap.catalog plan --catalog D:\WoWAssets\catalog.jsonl.gz --packages D:\WoWAssets\Packages --plan examples/void-crypt-entrance.json --out output/dependencies.json
```

Отчёт учитывает полы, стены, лестничные текстуры, M2, выбранный SKIN и реально
используемые текстуры материалов. Неиспользуемые LOD и материалы не требуют загрузки.

| Поле | Значение |
|---|---|
| `missing_packages` | Архивы из каталога, в которых находятся ещё недоступные ресурсы |
| `unavailable_resources` | Конкретные пути, которых нет в открытых ZIP |
| `not_in_catalog` | Путь отсутствует в полном переданном каталоге: скачивание уже известных пакетов его не добавит |
| `models_needing_inspection` | Нет M2/SKIN или не удалось завершить осмотр |
| `model_errors` | Причина ошибки разбора конкретного M2/SKIN |
| `dependencies_complete` | Все необходимые ресурсы доступны, материалы разрешены и проверка завершена |

Не подменять отсутствующую текстуру похожей без явного изменения задания.
Для гробов Duskwood недостающая `interface/glues/models/ui_scourge/cemetery01.blp`
отсутствует в текущем полном каталоге выгрузки. Это потребует отдельной выгрузки
ресурса из клиента; генератор не обещает найти её в произвольном соседнем ZIP.

## Обзор объектов до полного рендера

```console
python -m wowmap.review --plan examples/void-crypt-entrance.json --plan examples/void-crypt-passages.json --plan examples/void-crypt-sanctum.json --packages D:\WoWAssets\Packages --catalog D:\WoWAssets\catalog.jsonl.gz --out output/crypt-review
```

`review.json` содержит ошибки, предупреждения, количество повторений и источники
необходимых архивов. `objects-*.jpg` показывают разные сочетания модели, размера,
поворота и непрозрачности. Слева — вписанное превью, справа — **настоящий масштаб
карты**, без увеличения. Крупные изображения справа обрезаются с явной подписью;
полные прозрачные PNG находятся в `objects/`. Фон обзора не попадает на карту.
Тени размещения в доказательный спрайт не включаются.

Предупреждения о малой толщине проекции или низком тональном контрасте — подсказки
для осмотра, не автоматическое признание модели непригодной. Человек, создающий
карту, осматривает фигуру, назначение предмета, орнаменты, масштаб и силуэт.
Автор карты может быть ассистентом: этот шаг не требует отдельного разрешения пользователя.

Результат осмотра можно закрепить файлом:

```json
{
  "format": "wowmap.visual-decisions/1",
  "accepted": {
    "<signature из review.json>": "Проверены силуэт и рельеф в масштабе карты"
  }
}
```

Проверка `--decisions путь.json` отклонит отсутствующее/устаревшее решение для
каждого варианта модели, встречающейся суммарно восемь раз и более.
Изменение масштаба карты, размера, поворота, непрозрачности или исходного спрайта
меняет signature. Это контроль повторной проверки, а не алгоритм художественной оценки.
Ошибки рендера и неполные зависимости отклоняются независимо от числа размещений.

Сборщик крипты принимает этот же файл через `--visual-review` и проверяет его
до полноразмерного рендера. При этом проверка технических исходников и приемка
карты в установленной Foundry остаются отдельными этапами.

## Лестничный элемент

В `wowmap.scene/1` доступен массив `stairs`:

```json
{
  "stairs": [{
    "id": "descent",
    "asset": "dungeons/textures/stairs/jacryptstair.blp",
    "bounds": [17.35, 24.8, 22.65, 29.2],
    "steps": 8,
    "down": "south",
    "tile_cells": 2.65,
    "riser_fraction": 0.2,
    "depth_shade": 0.38,
    "tint": "#bdb8b0"
  }]
}
```

`bounds` — прямоугольник в клетках внутри карты. `steps`: 1..64; `down`:
`north`, `south`, `east`, `west`. Материал содержит светлую проступь в верхних
46% текстуры и тёмный подступенок ниже; подходит семейство текстур с таким
расположением рисунка, проверенное на `jacryptstair.blp`. Произвольная текстура
с другой разметкой не гарантирует правильного вида.
`tile_cells` задаёт повтор вдоль ширины ступени; `riser_fraction`: 0.05–0.45,
`depth_shade`: 0–0.6 (до 60% постепенного затемнения в направлении спуска).
Непрерывная фактура камня, подступенки и края ступеней строятся вместе.

Лестница рисуется поверх покрытий, под деталями/предметами и стенами. Она не
создаёт барьеров, Region или телепортации автоматически. Для разных уровней
переход остаётся нативным Region Foundry. Сетка в игровое изображение не запекается.

## Проверка на крипте DEV2

### Дополнительные исправления материалов и кэша

M2-материалы теперь соблюдают независимые флаги повторения текстуры по S/T.
Для неповторяющихся координат используется прижим к последнему текселю вместо
зацикливания на противоположный край. Это реальное исправление общего рендера;
оно не добавляет отсутствующие текстуры и не гарантирует художественную оценку.
Ключ дискового кэша включает отпечаток кода проектора/материалов и декодера BLP,
а также версии Pillow/NumPy. Старый спрайт после изменения этих частей не используется.
Подпись визуального осмотра дополнительно учитывает реальные пиксели конечного спрайта.

Диагностика sarcophagus.m2 подтвердила наличие рельефа рыцаря в исходной BLP,
большом превью и картографическом спрайте. При сжатии всей карты в обзор рельеф
теряется раньше контура. Это отдельный случай от отсутствия cemetery01.blp
у coffin.m2 и coffinlid.m2.

### Точечное восстановление отсутствующего файла

`recover_crypt_assets.bat` запускает `python -m wowmap.recover_assets`.
Выбрать папку Data клиента 3.3.5a. Инструмент ищет известный внутренний путь
непосредственно, в том числе через внешний список имён MPQ и локализованные архивы.
Прежняя выгрузка могла пропустить файл из-за отсутствия имени в listfile.
Это гипотеза до проверки на клиенте пользователя, а не утверждение, что файл там есть.

Результат: `output/missing-crypt-assets/recovery-report.json` и, если файл найден,
`recovered-crypt-assets.zip`. Отправить оба файла разработчику; полный клиент или
повторный многогигабайтный экспорт не нужны. Доступ к клиенту только на чтение.
Отдельные delta patch blobs не выдаются за готовые текстуры.

### Открытые и повреждённые захоронения

Массив `burials` создаёт явно спроектированные каменные конструкции:
`id`, `asset`, `bounds` в клетках, `state: "open" | "broken"`,
`blocks_movement` (по умолчанию true). Настоящая текстура камня формирует борта,
затемнённое дно и повреждённый угол. Экспортёр создаёт четыре стены движения,
не перекрывающие свет и зрение. Это не автоматическая конвертация закрытой M2
в открытую и не имитация загрузки отсутствующей текстуры.

Общий канон: [план крипты](VOID_CRYPT_BLUEPRINT.md).
На входе заменены пять плоских захоронений реальными людскими саркофагами;
введён текстурированный лестничный пролёт. В галереях и святилище исходная
модель уже имела видимый сверху рельеф рыцаря и меча, поэтому сохранена.
Проекция карты остаётся строго сверху, без сдвига пола относительно барьеров.
Пять новых саркофагов имеют барьеры движения по основанию, пропускающие свет/зрение.
Это физические препятствия, не реализация правил половинного укрытия D&D.
