# Формат сцены: местность, здания и расстановка

## Цель

Ассистент переводит запрос мастера в точный план, выбирает ресурсы и проверяет результат. Программа выполняет геометрию и отрисовку. Лагерь, таверна и мост — примеры документов одного формата, а не отдельные режимы движка. Встроенной языковой модели и автоматического понимания русского запроса в программе нет.

Цель проекта — поддерживать необходимые для кампании боевые карты. Это расширяемая система: необычная сцена может потребовать нового вида геометрии, подготовки модели или дополнительной обработки материалов. Текущая версия не гарантирует поддержку любой модели и любой сцены без доработок.

## Поддерживаемые возможности

- Экспорт без нарисованной сетки. `pixels_per_cell` остаётся в данных для настройки Foundry; `map-grid.png` больше не создаётся и удаляется при повторном рендере в ту же папку.
- Общий запуск `render_scene.bat`: выберите произвольный JSON сцены и папку ZIP-ресурсов.
- Текстурные полы и прямые стены произвольного направления, без обязательных готовых моделей домов.
- Двери, окна, проходы и частично разрушенные стены. Проёмы вырезаются из стены по тем же координатам, которые записываются в структурный JSON.
- Плавные пути Catmull–Rom, прямоугольники и вырезы внутри покрытий.
- Поворот покрытия, оттенок и мягкое смешивание двух вариантов текстуры для уменьшения заметного повторения. Масштаб покрытия остаётся явным.
- Детерминированная расстановка окружения с ограничениями: область, исключения, отступы от других объектов, полов и стен. Условия не ослабляются молча.
- Поиск в полном каталоге и список ZIP-пакетов, необходимых для сцены и известных зависимостей моделей.
- Опциональный WebP без потерь для уменьшения файлов. Старые планы по умолчанию сохраняются в PNG.

## Формат сцены

Формат остаётся `wowmap.scene/1`; старые планы совместимы.

Необязательные поля (базовые — в [SPECIFICATION_0.1.md](SPECIFICATION_0.1.md)):

| Поле | Значение |
|---|---|
| `export_format` | `png` (по умолчанию) или `webp` без потерь |
| `floors` | Слои покрытия с `id`, `asset`, `tile_cells`, `shape`; рисуются поверх обычной местности |
| `walls` | Текстурные отрезки стен с проёмами |
| `scatter` | Группы ограниченной расстановки объектов |
| `architecture` | Декоративная кромка и тень основания стены |
| `details` | Линии, прямоугольники, эллипсы и полигоны отделки |

Общий порядок: местность → полы → обычные объекты → стены/двери/окна → верхний слой. Мебель размещается внутри помещения явными координатами. Деревья и другой декор можно задавать явно или через `scatter`.

### Покрытия и формы

К обычным слоям и полам добавлены:

- `tile_rotation`: 0, 90, 180, 270 градусов.
- `texture_variation`: 0…0.5; плавно смешивает сдвинутый/повёрнутый вариант того же покрытия, без случайного поворота отдельных тайлов.
- `tint`: множитель цвета, например `#73b6df` для водной текстуры.
- `shape.type: rectangle` с `bounds: [x0,y0,x1,y1]`.
- `shape.smooth: true` для `path`.
- `shape.cutouts`: массив фигур, вычитаемых из покрытия.

Вода в примере использует статический кадр текстуры WoW. Это не анимированный шейдер воды. Новые формы совместно используются для изображения и проверки размещения; отступ от эллипса вычисляется приближённо.

### Стены и проёмы

```json
{
  "id": "south-wall",
  "points": [[3, 17], [23, 17]],
  "thickness": 0.35,
  "asset": "dungeons/textures/blackfathom/bm_bf_stonewall01.blp",
  "tile_cells": 1.8,
  "openings": [{
    "id": "entry",
    "type": "door",
    "at": 10,
    "width": 2,
    "state": "open",
    "asset": "dungeons/textures/floor/mm_inn_wood floor_01.blp"
  }]
}
```

Координаты и размеры — в клетках. `at` задаёт расстояние до центра проёма от первой точки стены. Проёмы не могут пересекаться или выходить за концы стены.

Типы: `door`, `window`, `passage`. Дверь/окно требуют текстуру полотна или рамы. Дверь может быть `open`, `closed`, `locked`; закрытая и запертая визуально одинаковы. Окно изображается рамой и условной полосой стекла. Рендер сохраняет визуальные и структурные данные. [Экспорт Foundry](FOUNDRY_EXPORT.md)
создаёт из них интерактивные двери и стены; арки остаются проходами.

### Ограниченная расстановка

```json
{
  "id": "forest",
  "count": 25,
  "region": {"type": "rectangle", "bounds": [0, 0, 36, 28]},
  "exclude": [{"type": "path", "points": [[0, 14], [36, 14]], "width": 4}],
  "size_range": [4, 6],
  "radius": 1.2,
  "prototypes": [{
    "model": "world/kalimdor/ashenvale/passivedoodads/ashenvaletrees/ashenvaletree02.m2",
    "layer": "overhead"
  }]
}
```

`radius` — упрощённый круговой отступ, а не извлечённый контур модели. Для явных объектов используется `keepout_radius` либо 1/4 их размера. Границы, исключения и промежутки проверяются по центру с этим отступом; края больших крон могут нависать над дорогой. Полы и стены автоматически учитываются. `avoid_floors: false` разрешает расстановку внутри полов. По умолчанию `strict: true`: если нужное количество не помещается, рендер останавливается с объяснением. `strict: false` сохраняет достигнутый результат и отчёт.

Seed выбирает размещение внутри заданного плана; сюжетную планировку составляет ассистент.

### Архитектурная отделка

`architecture` содержит `outline_cells` (0..0.2, по умолчанию 0), `shadow_cells`
(0..1, по умолчанию 0) и `shadow_opacity` (0..1, по умолчанию 0.25).
Это кромка среза и декоративное затемнение, не динамический свет или препятствие.

У каждого элемента `details` уникальный `id`, `type`: `line`, `rectangle`,
`ellipse` или `polygon`. Линия/полигон задаются `points`, прямоугольник/эллипс —
`bounds`. `fill` и `stroke` — цвета; `opacity` 0..1, `width_cells` (0..2],
по умолчанию 0.04. Эти детали рисуются под объектами, не создают стены Foundry.
Примеры применения — [«Старый дуб»](OLD_OAK.md).

## Поиск и подготовка ресурсов

```console
python -m wowmap.catalog search --catalog catalog.jsonl.gz --query "inn wood floor" --extension .blp
python -m wowmap.catalog plan --catalog catalog.jsonl.gz --plan examples/roadside-tavern.json --packages "D:\WoWMapTools\Packages" --out output/requirements.json
```

Поиск основан на именах и путях файлов. Он не распознаёт содержимое изображения. Проверка плана выдаёт точные пакеты для недостающих ресурсов. Если M2 ещё не скачан, ссылки на его материалы пока неизвестны — это явно указано в отчёте. Самостоятельного доступа программы к Google Drive нет; ассистент получает пакеты через подключение Drive.

## Проверочные сцены

Все используют тот же CLI и те же примитивы:

- `roadside-tavern.json`: первый этаж с залом, спальней, складом, мебелью, открытыми/закрытыми дверями и окнами.
- `forest-river-crossing.json`: извилистая река, берег, дорога, деревянный мост и деревья с защищёнными подходами.
- `overgrown-ruins.json`: каменный двор с вырезами покрытия, разорванные стены и окружение.
- `ashenvale-camp-objects.json`: исходный лагерь, обновлённые покрытия и экспорт без сетки.

Для новых примеров нужны также `dungeons-textures-c1558cc2-001.zip` и `xtextures-river-6e07a396-001.zip` из уже подготовленного набора; они есть в общем хранилище пользователя.

## Выходные данные

`map.png`/`map.webp` — основное изображение. Дополнительные слои используют то же расширение. `scene-plan.json` сохраняет исходное задание, `expanded-plan.json` — фактическую расстановку при наличии scatter; `placement-report.json` — результат ограничения.

`scene-geometry.json` содержит отрезки стен и проёмов в клетках, **не готовую сцену**.
Нативный экспорт выполняется после рендера: [FOUNDRY_EXPORT.md](FOUNDRY_EXPORT.md).
Он создаёт стены, двери, окна, свет и переходы между отдельными сценами этажей.

## Проверки

Проверены воспроизводимость и ограничения scatter, совпадение проёмов с геометрией, вырезы покрытия, отсутствие сетки и WebP без потерь. Дополнительно все три новые карты отрисованы из исходных ресурсов и визуально проверены. Расстановка не доказывает автоматическую тактическую проходимость или баланс сцены — это проверяется при авторской подготовке карты.
