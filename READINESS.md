# Проверка перед новой картой и NPC — 30.10.2026

Эта полная исходная сборка объединяет базу foundry-builder 06583bf011a5bc4db1265d67eaf0305bd2bd0f37, накопленные Profiles/VoidFX DEV2, исправления материалов 0.32 и рендера 0.35, а также текущую оптимизацию и проверки выпуска. Дополнительно накладывать прежние патчи не нужно. Исходные игровые архивы и локальные кэши сюда не входят.

## Рабочие программы

| Задача | Точка входа |
|---|---|
| Карты, стены, лестницы и экспорт | `python -m wowmap.run_scene --help` |
| NPC, способности, иконки, токен и портрет | `python tools/build_foundry_batch.py --help` |
| Отдельный лист без графической сборки | `python foundry_builder/build_npc.py --help` |
| Внешность обычных рас / явный DK-профиль | `python -m wowmap.character_variants --help` |
| Поиск ресурсов и всех зависимостей | `inventory/query.py` в отдельном WoW_Resource_Inventory_335a.zip |
| Быстрый локальный индекс игровых ZIP | `python -m wowmap.asset_index --packages ПАПКА` |
| Полная проверка кода этой сборки | `python tools/check_readiness.py` |

Для классов, подклассов и рас игроков используется отдельный Player_Character_Builder_DEV2; готовый контент — модуль WoW DnD5e; его актуальная версия указана в собственном module.json. Не заменяйте им NPC Builder: это разные программы. Встроенный wowmap-poses переключает подготовленные normal/combat снимки; это не универсальный выбор любых форм.

## Порядок подготовки контента

Сначала весь слой карт, по одной сцене. Затем обитатели, тоже по одной сцене. Несколько типов NPC для одной сцены — допустимый пакет. Не разрабатывать всех обитателей всех этажей одним проходом.

1. По справочнику выбрать реальные ресурсы и архивы зависимостей. Присутствие файла не означает его пригодность сверху.
2. Проверить исходный модельный спрайт и размер на карте до массового размещения. Лестница должна иметь видимый ориентир в обоих направлениях перехода, а не только Region.
3. Для каждого NPC отдельно выбрать позу, токен сверху и портрет. Рецепты опубликованного пакета используют yaw=-90 (или эквивалент 270); portrait_yaw независим. Движение и rotation размещённого токена этой проверкой не блокируются. Низкоуровневый preview оставляет свободный угол для диагностики.
4. Значки нужны предметам, действиям и эффектам. Пакетная сборка проверяет явно выбранные и выгруженные WoW-иконки. Один тип существа с вариантами показателей использует общий набор изображений/иконок.
5. Проверить экспорт, реальные стены, переходы, изображения и размещения. Художественный просмотр и живой игровой тест дополняют автоматические проверки.

## Действующие проверки выпуска

Архив иконок открывается один раз на пакетную сессию; при ошибке дескрипторы закрываются. Подписи, размеры, SHA256 исходных иконок и конечные пиксели сохраняются. Прямой одиночный вызов по-прежнему сразу закрывает ZIP.

Проверка выпуска отклоняет наклонённый токен и непроверенную отдельную иконку эффекта. Старые 11 рецептов крипты приведены к yaw=-90, портреты не изменены. Уже выпущенные карты, листы и медиа в мире Foundry не переписываются.

Объединены тесты обновлённого рендера, ранее поставлявшиеся отдельно от основной программы. Для исходных земляного элементаля, демона Бездны и суккуба добавлена повторяемая проверка `tools/audit_resource_subset.py`: оригинальные пакеты нужны отдельно. Она не заменяет полный клиент WoW.

## Ограничения

Не реализованы полный движок частиц, ribbons, billboarding, UV-анимация и все шейдеры клиента. Видео-тайлы окружения поддерживаются отдельно от статичного фона. Успешные статические зависимости не обещают поддержку всех эффектов и внешностей. Профиль normal исключает DK-варианты; пригодность конкретного лица и одежды всё равно проверяется превью.

Тесты импортёра и переключения поз используют имитацию Foundry API. Запущенный Foundry, Windows MPQ-библиотека и художественная приёмка новых сцен в этом проходе не проверялись.


## Вариативность внешности

Для случайной внешности и предметов используйте [CHARACTER_VARIANTS.md](CHARACTER_VARIANTS.md). Короткие подборки распределяются между телами/комплектами, фиксированные параметры учитывают зависимости DBC, equipment_pools выбирает предметы по слотам. Вторичные накладки лица/скальпа могут иметь явные предупреждения; основные материалы остаются обязательными. Аудит и контрольная подборка задаются tools/audit_customization.py и requests/character-wardrobe.json.
