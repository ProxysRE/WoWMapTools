# DEV0.3 preview 1 — зависимости и вид сверху M2

Первый технический этап поддержки объектов. Работает с ZIP-пакетами, созданными упаковщиком DEV0.2. Программа читает их напрямую без распаковки всего содержимого на диск. Требуются те же Pillow и NumPy.

```console
python -m wowmap.models audit --packages "D:\WoWMapTools\Packages" --filter ashenvale --out output/audit
python -m wowmap.models preview --packages "D:\WoWMapTools\Packages" --model "world/kalimdor/ashenvale/passivedoodads/ashenvaletrees/ashenvaletree02.m2" --out output/tree
```

В `--packages` укажите каталог с ZIP, а не распакованные каталоги. `audit` создаёт `audit.json`: прямые ссылки на текстуры, SKIN-файлы, отсутствующие ресурсы и заменяемые текстуры. `--filter ""` проверяет все M2 в доступных пакетах. Добавьте `--catalog путь/к/catalog.jsonl.gz`, чтобы отчёт указал точные ZIP-пакеты недостающих файлов.

`preview` сохраняет прозрачный `model.png` и `model.json` с проекцией точки привязки и масштабом. Отсутствующие зависимости вызывают ошибку; текстуры не заменяются выдуманными материалами.

## Поддержка и ограничения

- Только MD20/M2 v264 (WotLK) и внешний SKIN; первый профиль геометрии.
- Ортографическая камера сверху, глубина треугольников, UV и декодирование BLP через Pillow.
- Один материал/текстура на batch, режимы 0/1/2; полупрозрачность пока приближена отсечением.
- Статическая исходная геометрия: без вычисления скелета, UV-анимации, частиц, лент и billboarding.
- Заменяемые текстуры требуют выбора варианта и сейчас отклоняются.
- Это техническое превью, не точное воспроизведение освещения и шейдеров WoW. Не все M2 пригодны для такого режима.
- WMO, расстановка спрайтов на карте, автоматическое определение игровых границ и Foundry ещё не реализованы.

Дерево `ashenvaletree02` и камни `ashenvalerock01..04` проверены на исходных ресурсах: необходимые текстуры и SKIN присутствуют в стартовых пакетах. Некоторые другие деревья используют материалы соседних зон; эльфийские палатки — общую текстуру из `world/environment`.
