# DEV0.2 — подготовка графических ресурсов для Google Drive

**Отдельная выгрузка иконок:** `pack_icons.bat` проверяет также архивы папки языка.
См. [инструкцию по иконкам](ICONS_EXPORT.md). Остальная инструкция ниже описывает
прежний общий профиль графики; его область поиска не меняется.

Программа читает стандартные архивы WoW 3.3.5a **только для чтения** и создаёт самостоятельные ZIP-пакеты, каталог и несколько листов превью. Загрузка на Drive выполняется отдельно пользователем. Никаких аккаунтов, токенов или публичных ссылок программа не запрашивает.

## Получение готового инструмента Windows x64

1. На странице репозитория откройте **Actions → Windows packer**.
2. Выберите последний **успешный** запуск нужной ветки, внизу скачайте артефакт **WoWMapTools-DEV0.6.1-Windows**.
3. Распакуйте скачанный архив. Внутри находится `WoWMapTools-DEV0.6.1-Windows.zip`; распакуйте и его.
4. В папке программы запустите `setup_windows.bat` (Python 3.10+ **64-bit** с `py` launcher).
5. Запустите `pack_for_drive.bat`. В окне выбора укажите папку **Data** своего клиента.
6. Дождитесь завершения. По окончании откроется папка `output\drive-export\upload`.

Это отдельная сборка с необходимой `tools\StormLib.dll`. Обычный **Code → Download ZIP** содержит только исходники и не включает DLL. DLL собирается из фиксированной версии StormLib 9.40; её лицензия находится рядом.

Потребуется свободное место под извлечённые графические ресурсы. Размер выводится после индексации. Первичная обработка может занять существенное время, в зависимости от диска и объёма клиента. ZIP не содержит дополнительного сжатия: BLP и модели сохраняются без преобразования и потери качества.

## Что загрузить

Сначала проверьте `upload\summary.json`: поле `status` должно быть **complete**.

1. Создайте отдельную папку в своём Google Drive.
2. Загрузите туда **содержимое папки `upload`**, сохранив `packages` и `previews`.
3. Передайте ассистенту ссылку на папку. Первым делом будут прочитаны `summary.json`, `catalog.jsonl.gz` и превью; нужные ZIP выбираются по каталогу.

Можно сначала загрузить метаданные и один нужный пакет для проверки доступа к крупным файлам через подключение Drive. Успех самого экспорта ещё не подтверждает, что каждую ZIP-часть получится скачать в окружение ассистента; это проверяется отдельно. Делать папку общедоступной не требуется, если она доступна подключённому аккаунту.

**Не загружайте `work`, `.venv`, исходный клиент или папку программы.** Локальная папка `work` нужна для продолжения и не содержит полезных для выбора ресурсов превью.

## Состав результата

| Файл | Назначение |
|---|---|
| `summary.json` | Статус, предупреждения, объём и SHA-256 всех пакетов |
| `inventory.jsonl.gz` | Список обнаруженных эффективных графических файлов до извлечения |
| `catalog.jsonl.gz` | Путь/ID ресурса → ZIP и имя внутри ZIP |
| `packages/*.zip` | Самостоятельные пакеты примерно до 128 MiB, не тома одного архива |
| `previews/*.jpg` | Образцы основных текстур местности по зонам |
| `READ_ME.txt` | Короткое описание набора |

Модель может ссылаться на текстуры из **другого** пакета. Все исходные виртуальные пути сохранены в нижнем регистре; каталог позволяет найти зависимость. Автоматическая сборка зависимостей модели и подготовка вида сверху ещё не реализованы.

Сохраняются `.blp`, `.png`, `.dds`, `.tga`, `.m2`, `.mdx`, `.skin`, `.anim`, `.wmo`, `.adt`, `.wdt`, `.wdl`, `.dbc`. Звук, ролики и исполняемые файлы не выбираются. Превью ограничены образцами: максимум 64 группы местности по 8 текстур; остальные ресурсы доступны через каталог.

## Порядок архивов и полнота

Приоритет от низкого к высокому:

`common.MPQ → common-2.MPQ → expansion.MPQ → lichking.MPQ → patch.MPQ → patch-2.MPQ → patch-3.MPQ`

Для каждого виртуального пути берётся последняя доступная версия. Маркеры удаления исключаются. Промежуточные устаревшие копии не упаковываются.

Пакет предназначен для **именованных графических файлов из стандартных корневых архивов**. Это не полная резервная копия клиента:

- Локализованные архивы из папок языка и нестандартные/буквенные патчи не включаются.
- Отсутствующие стандартные архивы и безымянные записи отражаются в предупреждениях.
- При неполном списке имён можно передать `--listfile` с внешним текстовым списком путей.
- Delta-патчи явно отклоняются: программа не будет выдавать двоичную разницу за полноценную модель.
- Один ресурс больше 256 MiB останавливает экспорт. Если отдельный ресурс больше целевого ZIP, он получит собственную увеличенную часть; такие пакеты перечислены в `oversized_packages`.

`status=complete` означает, что **выбранный именованный набор** упакован успешно. Предупреждения о покрытии каталога всё равно нужно учитывать.

## Продолжение и диагностика

При остановке или ошибке не удаляйте результат. Повторный запуск с той же папкой Data и теми же параметрами проверит SHA-256 завершённых пакетов и продолжит с незавершённой группы. Повреждённые пакеты пересоздаются. Если исходные архивы изменились, выберите новую папку результата.

Техническая команда:

```console
.venv\Scripts\python.exe -m wowmap.pack --data "D:\Games\WotLK\Data" --out output\drive-export
```

Только каталог без извлечения:

```console
.venv\Scripts\python.exe -m wowmap.pack --data "D:\Games\WotLK\Data" --out output\drive-export --index-only
```

`--part-mib 64` уменьшает целевой размер пакетов. При смене размера нужна новая папка результата.

Загрузочные метаданные содержат имена архивов, их размеры/время изменения и виртуальные пути ресурсов. Абсолютный путь к установленному клиенту в них не записывается.
