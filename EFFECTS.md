# Эффекты WoW: рендерер и первый пилот

Первый профиль — `wow.fire.projectile`: огненный снаряд от центра одного токена
к центру выбранной цели. Модуль для **Foundry 13.351 / dnd5e 5.3.3**, с внешним
**Sequencer 3.6.11+**, совместимым с Foundry 13. Автозапуск изначально выключен.
Это пробный экспорт, который ещё требует проверки в работающем Foundry.

Готовый книжный модуль WoW DnD5e использует собственный встроенный адаптер:
в выпуске 0.40.24 доступны огонь, лёд, Тьма и Скверна (95 активностей).
Первый огненный выпуск пользователь подтвердил в Foundry; новые профили требуют
отдельной игровой проверки. Раздел установки ниже относится к самостоятельному
старому пилоту `wowmap-effects`, а не к книжному модулю.

## Установка готового пакета

1. Скопируйте каталог `wowmap-effects` из готового ZIP в `Data/modules`.
2. Установите/включите Sequencer и включите «WoWMap — эффекты способностей (пилот)».
3. Создайте Script-макрос из `macros/test-projectile.js` внутри каталога модуля.
4. Выберите свой токен и назначьте ровно одну цель. Запустите макрос.
5. После проверки используйте Script-макрос `macros/bind-projectile.js`: выберите
   конкретную активность предмета или заклинания. Затем включите настройку
   «Автозапуск привязанных эффектов» в настройках модуля.

Привязка хранится в `item.flags.wowmap.visuals.activities[activityId]`.
Имя предмета и язык не используются для сопоставления. Тем же макросом можно
снять привязку. Удаление/пересоздание активности потребует повторного назначения.
В билдере отдельное поле визуального профиля пока не добавлено.

При включённой автоматике эффект запускается по `dnd5e.postUseActivity` только
на клиенте автора сообщения об использовании. Повторные вызовы для того же
сообщения и активности подавляются. Броски атаки и урона не подписаны; хук не
блокирует последующее действие системы. Sequencer отвечает за показ другим
клиентам. Состояние мира, расход ресурсов, урон и положение токенов не меняются.

Источник определяется по актёру активности. Если на сцене несколько его токенов,
должен быть выбран ровно один. Нужна одна видимая цель текущей сцены. Без цели,
при нескольких целях или неоднозначном источнике эффект пропускается с сообщением.
Проверка успешного попадания не выполняется: это визуализация запуска снаряда.

Вспышка попадания, звук, площадные шаблоны, самонаведение и интеграция с Midi-QOL
пока не включены. При совместном использовании с Automated Animations назначьте
для этой активности только один механизм визуализации, иначе оба модуля могут
показать свои эффекты. Пилот не изменяет настройки других модулей автоматически.

## Воспроизводимая подготовка графики

Из корня репозитория:

```console
python -m wowmap.effects --assets D:\WoWAssets --out output/fire-projectile
```

Требуются зависимости из `requirements.txt` и `ffmpeg` с `libvpx-vp9` в PATH.
Каталог результата должен быть пустым. Частные ZIP ресурсов должны содержать:

- `spells/fireball_missile_high.m2`;
- `spells/lensflare1.blp`;
- `particles/breath24.blp`;
- `creature/golemharvest/red_glow3.blp`;
- `spells/t_vfx_fire_anim02_64.blp`.

Рендерер читает исходные эмиттеры M2 v264, их постоянные параметры рождения,
кости и кривые жизни, цвета, прозрачности и размера. Случайность фиксирована.
Результат — циклический VP9 WebM с альфа-каналом, 384×384, 30 кадров/с,
длительность цикла от 1 до 15 секунд в зависимости от жизни частиц и анимации. В отчёте находятся SHA-256 источников и ограничения.
Для пакета скопируйте `fire-projectile.webm` в
`foundry_modules/wowmap-effects/media/` перед упаковкой модуля. Байты ресурсов
WoW, готовые WebM и кадры не коммитятся в git.

Это **упрощённая двумерная интерпретация частиц**, а не полный рендер WoW.
Для льда добавлено геометрическое ядро со скелетной позой, для льда и Тьмы —
ленты с исходными костями, цветом, шириной и текстурой. Ленты проецируются в
двумерные полосы с приближённой ориентацией камеры. UV-анимация, столкновения,
глубина и полный набор флагов частиц не реализованы. Плоское и сферическое рождение, последовательность кадров
атласа и след приблизительны; скорость следа выбрана для нашего 2D-профиля.
Чёрная подложка огненного атласа удаляется при подготовке. Сложение свечения
приближённо переводится в обычную RGBA-прозрачность. Выбор моделей ограничен четырьмя явными профилями; step/linear-параметры рождения читаются из M2/ANIM, включая global sequences.
Неподдерживаемые материалы лент явно отклоняются. Длительность жизни частиц
ограничена 15 секундами. Для Тьмы учитывается предыдущий цикл рождения,
поэтому частицы с жизнью 1.5 секунды не обрываются через секунду.

Размер видимого ядра меньше полной текстуры из-за пространства под свечение
и след. В Sequencer полная текстура имеет ширину 6 клеток; исходная точка ядра
задана `spriteAnchor({x:0.625,y:0.5})`. Она движется к центру цели со скоростью
8 клеток/с, с ограничением общей длительности 0.15–5 секунд. Точки фиксируются
при запуске, перемещение цели не отслеживается.

Для новых профилей используйте тот же CLI:

```console
python -m wowmap.effects --assets D:\WoWAssets --out output/frost-projectile --profile wow.frost.projectile
python -m wowmap.effects --assets D:\WoWAssets --out output/shadow-projectile --profile wow.shadow.projectile
python -m wowmap.effects --assets D:\WoWAssets --out output/fel-projectile --profile wow.fel.projectile
```

Нужны ZIP spells, particles, item/objectcomponents (blue_glow2),
creature/golemharvest. Исходные модели: `frostbolt.m2`,
`shadowbolt_missile.m2`, `fel_fireball_missile_high.m2` в каталоге spells.
Точные выбранные ресурсы с SHA-256 находятся в отчёте каждой сборки.
Файл эффекта соответствует профилю: frost-, shadow- либо fel-projectile.webm.
Самостоятельный старый адаптер пока предоставляет только огненный профиль;
новые профили автоматически подключаются в актуальном книжном модуле.

## Проверки и исходные контракты

- Python-проверки: нормализация времени частиц, отказ на меняющихся эмиттерах,
  прозрачность чёрного additive-texel и обрезка спрайта по границам.
- Node-проверка имитирует API Foundry/Sequencer: источник, цель, масштаб,
  единственный сетевой запуск, разрешения, снятие привязки и пропуск лишних хуков.
- Настоящий файл отдельно проверяется декодированием VP9 с альфа-каналом.
- Проверка с двумя подключёнными пользователями в Foundry остаётся отдельным шагом.

Сверка форматов/API:
[структура M2 в WoWModelViewer](https://github.com/wowmodelviewer/wowmodelviewer/blob/master/src/games/wow/modelheaders.h),
[описание M2Particle v264](https://github.com/paalgyula/summit/blob/development/pkg/converter/m2/m2.go),
[Sequencer 3.6.11 Effect API](https://github.com/fantasycalendar/FoundryVTT-Sequencer/blob/3.6.11/docs/api/effect.md),
[хук активности dnd5e 5.3.3](https://github.com/foundryvtt/dnd5e/blob/release-5.3.3/module/documents/activity/mixin.mjs).

## Лучевые эффекты

Отдельный рендерер `python -m wowmap.beams` и адаптер растягиваемой полосы описаны
в [руководстве лучей](BEAMS.md). Они используют SpellChainEffects и оригинальные
текстуры, не растянутый видеоролик снаряда. Старый самостоятельный огненный пилот
остаётся без изменений; автоматические лучи подключены в книжном модуле 0.40.25.


## Доработки 10 ноября 2026

Рендерер читает скалярные параметры рождения с интерполяцией step/linear из
локальных, внешних и глобальных последовательностей. Меняющаяся частота
эмиссии интегрируется с шагом 1/240 секунды. Возраст и параметры каждой частицы
отсчитываются от её рождения. Период циклического экспорта согласуется с
анимацией; неподходящий или чрезмерно дорогой цикл явно отклоняется.

Для явного M2-пути доступны неподвижный режим и одноразовый клип:

```console
python -m wowmap.effects --assets D:\WoWAssets --out output/acid --model spells/acid_ground_cloud.m2 --stationary
python -m wowmap.effects --assets D:\WoWAssets --out output/arcane --model spells/arcaneexplosion_base.m2 --stationary --duration 2
```

Это экспорт **слоя частиц**, а не обещание полного M2-эффекта: геометрия ядра
по-прежнему добавляется только для нашего ледяного профиля. Пользовательская
модель не получает автоматическую привязку заклинанию и имеет profile=null
в отчёте. Одноразовый клип с --duration не объявляется бесшовным.

Пределы: жизнь до 15 секунд, 12 000 частиц, 1 000 000 пар частица/кадр.
Модельные/рекурсивные частицы теперь явно отклоняются, а не молча теряются.
Hermite/Bezier, анимированные ленты и многотекстурные шейдеры остаются
отдельными ограничениями. Наличие файла не доказывает правильный рендер.

В общем просмотрщике исправлен M2Batch.textureCoordComboIndex: смещение 18
вместо materialLayer на смещении 12. Это устраняет ошибочное обращение к
таблице UV по номеру слоя. Источник полей:
[M2Batch](https://zxgit.org/RomanRom2/thunderbrew/src/commit/55bcd21c1fb2a1b1d078277d05c7d6c61ebd58d5/src/model/M2Data.hpp).
