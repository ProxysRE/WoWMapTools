# Токены существ: первый рабочий этап

Цепочка **ID облика → DBC → M2 и выбранные текстуры → токен сверху + портрет анфас**
работает на настоящей выгрузке. Проверены display ID **165, 644, 776**:
лесная, чёрная и белая окраски волка. Рендер использует статичную исходную позу,
два независимых ортографических ракурса одной внешности. Скелетные позы и сборка
одетых гуманоидов ещё не реализованы.

## Поиск и отдельный рендер

```console
python -m wowmap.tokens search --dbc-assets "D:\WoWAssets\DBC" --query "wolf timber" --limit 10
python -m wowmap.tokens render --dbc-assets "D:\WoWAssets\DBC" --model-assets "D:\WoWAssets\Models" --display-id 165 --size 512 --yaw -90 --portrait-size 768 --portrait-yaw 0 --out output/wolf
```

В папках ресурсов должны быть ZIP из прежних выгрузок. Поддерживается плоская
раскладка и подпапка `packages/`. Для скорости лучше собрать необходимые пакеты
модели в отдельную папку. Поиск использует английские пути моделей и имена скинов;
разные ID могут иметь одинаковую внешность. Ресурсы не скачиваются программой из сети.

Выход: `wowmap/content/tokens/<SHA-256>.webp`, отдельный портрет
`wowmap/content/portraits/<SHA-256>.webp` и `token-report.json`. Отчёт содержит
ID, модель, выбранные текстуры, хеши DBC и ресурсов, параметры и ограничения рендера.
Размеры обоих ракурсов — 64..2048 пикселей, углы — -360..360 градусов.
По умолчанию токен — 512 пикселей, yaw -90; портрет — 768, portrait_yaw 0.
Оба вписаны в прозрачные квадраты. Портрет снят со стороны +X модели: экран вправо
соответствует +Y, вверх — +Z; глубина учитывается со стороны камеры. Это отдельный
рендер, а не поворот или отражение вида сверху. Портрет имеет отступ не меньше 5%
с каждой стороны (минимум 8 пикселей), включая видимые крайние точки модели.
У зверя голова может закрывать часть тела в анфас; это естественное перекрытие,
не обрезание изображения. Размер **в клетках Foundry** задаётся
листом или размещением; масштабы WoW записываются в отчёт, но не переводятся в D&D.

## Вместе с Builder

В элемент задания добавляется поле:

```json
"appearance": {"display_id": 165, "size": 512, "yaw": -90, "portrait_size": 768, "portrait_yaw": 0, "actor_image": true}
```

Оно допустимо только для NPC. Вид сверху назначается `prototypeToken.texture.src`,
а отдельный фронтальный портрет при `actor_image:true` (по умолчанию) — основному `img`.
При `false` существующий портрет сохраняется, новый фронтальный файл не создаётся.
Нельзя назначать иконку и модель одному полю одновременно.
Внешность не меняет тип, характеристики, атаки или способности листа.

```console
python tools/build_foundry_batch.py requests/builder/tokens-demo.json --dbc-assets "D:\WoWAssets\DBC" --model-assets "D:\WoWAssets\Models" --out output/wolves
```

Пример содержит три **технических**, не боевых листа: все характеристики 10, КД 10,
1 хит, скорость 0, Средний размер, CR 0, без атак, способностей, особых чувств и языков.
Источники основаны на `templates.npc` и проходят настоящий Builder.

Результат включает оба вида изображений и `population.json`. Прежняя команда
`wowmap.population` переносит оба ракурса в экспорт карты, проверяя файлы и хеши до записи.
Пакетная сборка при ошибке не публикует неполный результат.

## Проверка в Foundry

1. Скопируйте папку `wowmap` в пользовательскую **Data сервера Foundry**, объединив
   её с прежними картами и иконками.
2. Создайте временный NPC и импортируйте в него `wolf-timber.json` обычным импортом JSON.
   При желании повторите для остальных окрасок.
3. Перетащите **нового** NPC из списка актёров на любую сцену. Проверьте прозрачность,
   поворот и размер. Старые токены на сценах импорт листа не обновляет.
4. Откройте портрет в листе актёра и покажите его игрокам штатными средствами Foundry:
   там должен быть анфас, в то время как на сцене остаётся вид сверху.

В новых изображениях направление по умолчанию исправлено: голова смотрит вниз,
в соответствии с нулевым поворотом Foundry. Старые файлы/токены не меняются.
Если ранее вручную включали отражение, для нового изображения отключите его.
При явном `yaw` автор задания сам отвечает за направление.
Соглашение Foundry: https://foundryvtt.com/article/media/#token-orientation

Таверна не нужна. Отчёты и `population.json` не импортируются как листы.
Цели — Foundry 13.351 / dnd5e 5.3.3; игровой тест остаётся за пользователем.

## Поддержка и ограничения

Используются схемы WoWDBDefs для **3.3.5.12340**: CreatureDisplayInfo — 16 полей,
CreatureModelData — 28. Проверяются размеры записей, уникальность ID и ссылки.
Номер сборки не угадывается из заголовка WDBC. `.mdx` разрешается в `.m2`, текстуры
типов 11–13 берутся из TextureVariation, без случайных подстановок.

- https://github.com/wowdev/WoWDBDefs/blob/master/definitions/CreatureDisplayInfo.dbd
- https://github.com/wowdev/WoWDBDefs/blob/master/definitions/CreatureModelData.dbd
- https://github.com/wowmodelviewer/wowmodelviewer/blob/master/src/games/wow/wow_enums.h

Сейчас нет вычисления костей, анимаций, UV-анимации, частиц, лент и billboarding.
Поддерживается одна текстура на batch, режимы 0/1/2/4; полупрозрачность режима 2 приближена
отсечением. Гуманоиды с ExtendedDisplayInfo, модели `character/`, специальные geoset
и полупрозрачные облики отклоняются явно. Иные материалы тоже могут потребовать доработки.
DBC не заменяет серверную базу или D&D-статблоки.

[Исправления мурлока и кобольда](MODEL_FIXES.md): additive-отражение со сферическими UV
и проверка только реально используемых ресурсов выбранного SKIN.

Обычный hosted runner GitHub автоматически не получает приватные ресурсы Drive.
CI проверяет искусственные M2/DBC/текстуры; реальный комплект собран ассистентом
с доступом к приватной выгрузке. Графика WoW в публичный git не добавляется.

Следующие этапы: скелетные позы, выбор частей геометрии, сборка кожи/лица/волос,
одежды гуманоидов, затем оружие и навесная экипировка.
