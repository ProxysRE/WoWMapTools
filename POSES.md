# Позы и переключение изображений

Целевая версия: **Foundry 13.351 / dnd5e 5.3.3**, ресурсы **WoW 3.3.5a**.
Рендерер рассчитывает один кадр скелетной анимации M2 и сохраняет обычные WebP.
Модуль Foundry переключает эти готовые изображения. Проигрывания анимации нет.

## Выбор позы

Поле `pose` находится внутри `appearance`, рядом с `character` или `display_id`.
Одинаково применяется к токену сверху и портрету.

| Значение | Результат |
|---|---|
| Нет поля или `"bind"` | Прежняя базовая геометрия; прежние изображения сохраняются |
| `"idle"` | Кадр Stand, 35% длительности |
| `"combat"` | Доступная стойка готовности под снаряжение, либо кадр атаки |
| `{"animation_id": 17, "fraction": 0.4}` | Выбранный кадр Attack1H |
| `{"animation_id": 60, "variation": 0, "time_ms": 500}` | Точный момент выбранной анимации |

Нельзя одновременно задавать `fraction` и `time_ms`. Fraction: 0..1;
time_ms: 0..длительность. Несуществующая анимация или вариация — ошибка.
В автоматическом режиме выбирается существующая анимация; её ID, индекс,
разрешённый alias, длительность и момент записываются в `render.pose` отчёта.
Для зверя без ReadyUnarmed используется AttackUnarmed, без подмены моделью человека.

Поддерживаются иерархия костей, взвешенная деформация позиций и нормалей,
поворот вокруг pivot, translation/rotation/scale, step/linear, SLERP,
глобальные последовательности и внешние `.anim`. Их SHA-256 входят в источники.
Пустой трек сохраняет исходное положение. Повреждённые данные, циклы и неподдерживаемая
интерполяция вызывают ошибку. Нулевой масштаб скрытых частей допустим.

Экипировка переносится матрицей родительской кости. Плащ деформируется как часть тела.
Для рук с оружием используется HandsClosed по ключевым костям пальцев, когда эта
анимация есть у модели. У двуручного оружия закрываются обе руки, у лука — рука с луком.
В явной позе `"close_hands": false` отключает наложение хвата.
Точная посадка второй руки на произвольное оружие не решается обратной кинематикой.

Нет динамики ткани, частиц, эффектов зачарований, UV/цветовой анимации и
ориентации billboard-костей к камере. Такие кости сохраняют вычисленный скелетный
поворот; список затронутых костей находится в отчёте.

## Два облика в пакетном Builder

Вместо `pose` задаётся `pose_variants`:

```json
{
  "character": {"race": "human", "gender": "male"},
  "equipment": {"main_hand": 25, "off_hand": 143},
  "portrait_yaw": 30,
  "pose_variants": {
    "normal": "idle",
    "combat": "combat"
  }
}
```

В каждом значении допустима явная анимация, как в таблице выше. Нужны ровно
`normal` и `combat`. Builder записывает четыре пути в `flags.wowmap.poseVariants`
актора, назначает обычные изображения и начальный флаг прототипа `wowmap.pose`.
`actor_image: false` оставляет портрет прежним. Ресурсы обоих обликов включаются
в выходной каталог. Без `pose_variants` никаких данных модуля не добавляется.

Воспроизводимый набор: [pose-demo.json](requests/builder/pose-demo.json).

```console
python tools/build_foundry_batch.py requests/builder/pose-demo.json --dbc-assets D:\WoWAssets\DBC --model-assets D:\WoWAssets\Models --out output/pose-demo
```

## Модуль Foundry

Исходники: [wowmap-poses](foundry_modules/wowmap-poses).

1. Скопировать `wowmap-poses` в `Data/modules`, перезапустить Foundry.
2. Включить **WoWMap — позы токенов** в управлении модулями мира.
3. Скопировать графику `wowmap` в `Data` и импортировать новые JSON NPC.
4. Поставить NPC на сцену, открыть меню токена правой кнопкой мыши.
   Справа появится кнопка переключения обычного/боевого облика.

Нужны права владельца токена и, при смене портрета, актора. Перед изменением
модуль проверяет загрузку обеих картинок. ХП, предметы, эффекты, вращение,
размер токена и его прототип не меняются. Автоматической реакции на инициативу нет.
Облики сохраняются после перезагрузки мира.

**Независимые NPC:** у токена отключить Link Actor Data. Тогда портрет меняется
у его synthetic actor. У связанных токенов портрет общий, как и весь связанный
Actor; переключение его портрета будет видно другим связанным копиям.
Изображение на сцене меняется только у выбранного токена.
Демонстрационные NPC подготовлены с отключённой связью.

API для Script-макроса:

```js
const api = game.modules.get("wowmap-poses")?.api;
if (!api) return ui.notifications.warn("Включи WoWMap — позы токенов");
for (const token of canvas.tokens.controlled) await api.togglePose(token);
// Или await api.setPose(token, "combat"), await api.setPose(token, "normal").
```

Модуль не создаёт недостающую графику старых NPC: их нужно пересобрать с
`pose_variants`. Нативная игровая проверка модуля проводится отдельно от
автоматических проверок с имитацией API и DOM.
