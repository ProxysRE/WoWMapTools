# Foundry JSON Builder: GitHub и население карт

**Добавлено:** [иконки WoW в готовых JSON и населении карты](BUILDER_ICONS.md).
Пакетный инструмент назначает значки, конвертирует BLP и включает изображения
в результат; для этого среде сборки нужен отдельный приватный набор иконок.

**Добавлено:** [статичные токены существ по ID облика](TOKENS.md). Заданию с
`appearance` нужны также `--dbc-assets` и `--model-assets` в среде сборки.

Рабочая ветка — **foundry-builder** в репозитории WoWMapTools. Генератор карт и билдер находятся в одной ветке, чтобы собирать совместимые комплекты. Стабильная версия генератора карт остаётся в main.

## Перенос исходников

Каталог `foundry_builder/` содержит канонический проект из `FoundryVTT_Builder_Project.zip`, версия приложения **1.5**. Состав определяется `PROJECT_MANIFEST.json`; после первоначального переноса руководства актуализируются вместе с кодом. Исходный архив в ChatGPT Library сохраняется как исходная копия; текущая разработка этой интеграции ведётся в GitHub.

Точка входа в правила контента — `foundry_builder/AI_FOUNDRY_BUILDER_GUIDE.md`. Шаблоны, проверки и контракт activities/Active Effects сохраняются. Изменения самого билдера по-прежнему требуют его аудита и проверенной сборки через `package_project.py`. Для переноса готового JSON через оболочку канонические файлы менять не нужно.

Цели билдера: Foundry **13.351**, dnd5e **5.3.3**, Midi-QOL **13.0.64**, DAE **13.0.29**. Исходящие документы имеют совместимую отметку core 13.347, как в исходной программе. Это не меняет версию dnd5e.

## Сборка через GitHub Actions

Workflow **Foundry JSON Builder** автоматически запускается при изменении исходников билдера или `requests/builder/**` в этой ветке. Проверенный способ запуска сейчас — записать задание в `requests/builder/active.json` и отправить изменение в foundry-builder. Результат находится в Actions → Foundry JSON Builder → соответствующий запуск → Artifacts.

По умолчанию собирается **requests/builder/active.json**. Он содержит список документов с режимом и путём к исходнику. Ассистент может записать очередное задание в ветку; push запускает сборку. Листы без `icons`, `item_icons` и `appearance` выполняются на GitHub без обращения к вашему компьютеру и без ресурсов WoW. Задания с графикой требуют ресурсы в среде сборки; автоматически с Drive они не загружаются.

Артефакт **foundry-json-build** содержит:

- готовые JSON актёров, предметов и заклинаний;
- индивидуальные отчёты и общий `build-report.json`;
- `population.json` с актёрами и размещениями, если в задании есть NPC;
- проверенный архив **FoundryVTT_Builder_Project.zip** с обычным приложением для Windows.

Срок хранения Actions-артефакта — 30 дней. Готовые результаты можно скачать или передать отдельным постоянным файлом. Никакие сообщения, релизы и внешние публикации при сборке не создаются.

Тестовое задание собирает Марту (хозяйку), Орена (повара), ключ от кладовой и авторский демонстрационный заговор. NPC — мирные демонстрационные листы для проверки импорта, не готовые боевые противники. Результат проверяется настоящим `builder_app.build_document`, а не имитацией.

Обычные JSON собираются всеми соответствующими режимами исходного билдера. Режим `enhancement_set` создаёт устанавливаемый ZIP с LevelDB и дополнительно требует Foundry CLI (`@foundryvtt/foundryvtt-cli`), как исходная программа. Его установка пока не входит в workflow. При отсутствии зависимости задание завершится ошибкой, а не выдаст неподготовленный набор за готовый модуль.

## Локальная пакетная сборка

```console
python tools/build_foundry_batch.py requests/builder/active.json --out output/builder
```

Пути задания и исходников — относительно корня репозитория. Они должны вести к JSON внутри репозитория. Каталог результата должен отсутствовать или быть пустым. Сначала собираются и проверяются все документы; при ошибке неполный комплект не публикуется. Графическое приложение запускается прежним способом: `foundry_builder/start_builder_app.bat`.

Пример задания:

```json
{
  "format": "foundry-builder.batch/1",
  "documents": [
    {"id":"marta", "mode":"npc", "source":"requests/builder/sources/marta.json"}
  ],
  "placements": [
    {"id":"marta-reception", "actor":"marta", "scene":"ground",
     "position":[23.1,20.5], "disposition":"neutral", "actor_link":true}
  ]
}
```

`id` — стабильный ключ сущности, не имя файла с произвольным путём. Режимы: npc, feat, weapon, equipment, spell, consumable, item, enhancement, enhancement_set. Поля и смысл исходника задаются профильными руководствами билдера.

## Связь с картой

Сформированный **population.json** можно присоединить к свежему экспорту сцены:

```console
python -m wowmap.population --bundle output/inn/wowmap/my-inn/bundle.json --population output/builder/population.json
```

Команда добавляет актёров и токены в комплект, обновляет отдельные scene.json и макрос импорта. Её выполняют **до импорта в Foundry**, для ещё не заселённого экспорта. После команды архив комплекта необходимо перепаковать.

Параметры размещения:

- `actor` — ключ собранного NPC, `scene` — ключ этажа в плане карты;
- `position` — **центр токена в клетках**, преобразуется в координаты верхнего левого угла Foundry;
- `actor_link:true` — общий лист именованного NPC; `false` — отдельное состояние экземпляра токена;
- `disposition`: friendly, neutral или hostile;
- `width`, `height` — необязательный размер в клетках; по умолчанию берётся из прототипа;
- `hidden` — скрытое размещение; `elevation` — высота в единицах сцены.

Неуказанные `actor_link`, `disposition`, `hidden`, `elevation`, `width` и `height`
наследуются из прототипа токена NPC. Если их нет и в прототипе, используются
общий лист, нейтральное отношение, видимость, высота 0 и размер 1×1.
Явное значение размещения, включая `false` и `0`, имеет приоритет.

Прикрепление проверяет ключи, границы карты и повторные ID. В готовом комплекте стабильные ID связывают токены с актёрами. Новый импортёр проверяет версию dnd5e, наличие файлов, схемы и конфликты перед изменениями; сначала создаёт NPC, затем сцены. Существующие документы не перезаписываются. При серверной ошибке после создания NPC они могут остаться в мире; автоматического удаления нет.

Крупная мебель и стены не анализируются заново при размещении NPC: координаты выбирает автор сцены. Модуль не делает автоматическую симуляцию быта, не строит диалоги и не оживляет NPC. Облики WoW, отдельные токены и портреты подключаются через `appearance` в пакетном задании; подробности в `TOKENS.md`.

## Граница выполненного

Реализованы пакетная сборка настоящим билдером, запуск Actions, формат населения, присоединение к сценам и импорт актёров с привязанными токенами. Встроенные проверки охватывают ссылки, координаты, повторный импорт, порядок создания и остановку до записи при ошибках.

Игровой тест нового импорта актёров и токенов в Foundry ещё требуется. Ранее пользователь подтвердил стены, двери и межэтажные переходы экспортёра карт; это не заменяет проверку добавленной части населения. Рендер карт на GitHub по-прежнему требует доступа к ресурсам WoW или настроенного исполнителя; сборка листов этих ресурсов не требует.
