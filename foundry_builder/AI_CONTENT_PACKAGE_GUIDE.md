# Контент персонажей: единый сборщик наборов

Контракт пакета 4.0. Цель: Foundry VTT 13.351 / dnd5e 5.3.3.
Точка входа — `character_builder.py`. Все необходимые сборщики и runtime
находятся в этой программе; проект конкретного сеттинга не требуется.
Схемы 1–3 сохранены для прежних пакетов классов и рас.

## Книга → исходники → модуль

Книгу читает автор/ассистент. Сборщик принимает проверенный JSON, а не PDF.
За проход переносите одну расу или один подкласс со всеми его особенностями.
Запишите редакцию, хеш книги и страницы; сверьте уровни, выборы, ограничения,
источники, стоимость и восстановление ресурсов. Полный исходный текст сохраняйте.

Для особенностей используйте `AI_FEATURE_JSON_GUIDE.md` и актуальные
`docs/FEATURES_JSON.md`. Для заклинаний — `docs/SPELLS_JSON.md`.
Подробные форматы class/subclass — `AI_CLASS_SUBCLASS_JSON_GUIDE.md`.
Предыстории — `docs/BACKGROUNDS_JSON.md`.

## Формат schema 4

```json
{
  "schema_version": 4,
  "identifier": "example-content",
  "name": "Пример контента",
  "rules": "2014",
  "strict_automation": true,
  "external_classes": ["fighter"],
  "subclasses": [{
    "name": "Проверочный путь",
    "identifier": "example-path",
    "class_identifier": "fighter",
    "advancement": []
  }],
  "races": [],
  "backgrounds": [],
  "features": [],
  "feats": [],
  "spells": []
}
```

Полный пример всех пяти категорий — `examples/standard_options.json`.
`examples/content_package.json` проверяет прежний авторский класс с подклассами.
Оба примера технические, не представляют контент книги.

Допустимы наборы только с расами, только предысториями, только подклассами,
только общими чертами или только заклинаниями. Пустой набор запрещён.
Новые возможности предысторий, общих черт и внешних классов требуют schema 4.
`rules` — `2014` или `2024`; явные source.rules нативных экспортов не заменяются.

Вместо объектов доступны `class_file`, `subclass_files`, `race_files`,
`background_files`, `features_file`, `feats_file`, `spells_file`.
Первые файлы содержат один объект, последние три — массивы. Пути относительны
файлу набора. Объект/массив и соответствующие `_file`/`_files` одновременно
запрещены. Старые `subclass` и `subclass_file` поддержаны.

## Стандартные классы без копирования

`external_classes` перечисляет существующие стандартные классы, к которым
относятся новые подклассы. Поддержаны точные identifier:
barbarian, bard, cleric, druid, fighter, monk, paladin, ranger, rogue, sorcerer,
warlock, wizard. `class_identifier` подкласса должен точно совпадать.
Опечатка или необъявленный родитель блокируют сборку. Одновременно объявлять
один класс локальным и внешним нельзя.

Внешние классы не включаются в модуль и не изменяются сборщиком. При импорте
игрок использует соответствующий стандартный класс правильной редакции.
Объявление не доказывает, что класс установлен в мире. Выбор подкласса нужно
проверить в браузере компендиумов или перетаскиванием на лист на нужном уровне.

## Ссылки и отдельные каталоги

- `features`: компактные особенности с key `feature:identifier`.
- `feats`: самостоятельные черты с key `feat:identifier`.
- `spells`: Item типа spell с `system.identifier`; в schema 4 они проходят
  настоящий `spell_builder`, поддерживают mechanics и получают стабильный ID,
  если исходник не содержит `_id`.
- `races` и `backgrounds`: компактные или полные нативные документы.

В ItemGrant.items и ItemChoice.pool применяйте `feature:...`, `feat:...`,
`spell:...`, либо `{"ref": "feat:..."}`. Сборщик разрешит ссылки и при упаковке
перенесёт их на UUID конечного модуля. Внешние UUID не переписываются; их наличие
в установленной версии системы должен проверить автор. Общая черта может
выдавать связанную особенность или заклинание через своё advancement.

Все features обязаны быть достижимы из расы, класса, подкласса, предыстории
или общей черты. Каталожные feats и spells в schema 4 самостоятельны: отсутствие
выдачи через ItemGrant не означает потерю. Каталог заклинаний сам по себе не
настраивает списки выбора заклинаний стандартного класса и не добавляет их
персонажу. Такой список требует отдельной подтверждённой настройки.

Повторные ID/identifier, неразрешённые локальные ссылки, потерянные особенности,
ошибки automation и необъявленные общие ресурсы блокируют сборку.

## Раса и предыстория

Раса экспортируется как Item race. Размер, чувства, тип существа, скорость и
начальные бонусы задаются явно. Начальный уровень advancement — 0, последующие
расовые заклинания используют уровни персонажа. Вариант подрасы уже включает
общие и свои черты; одновременно добавлять базовую расу и вариант не нужно.

AbilityScoreImprovement поддерживает points, cap, fixed и locked. Если книга
разрешает +2/+1 либо +1/+1/+1, подходят 3 очка с cap 2. Для строго +2/+1
добавьте проверку распределения или отдельные варианты; не заявляйте свободные
3 очка точной автоматизацией такого ограничения.

Предыстория экспортируется как Item background, с развитием уровня 0.
Нативные выборы startingEquipment сохраняются. Текстовая выдача вещей,
особые сюжетные условия и отложенное получение владений не автоматизируются
сами по себе — укажите ручные части явно.

## Особенности и автоматизация

Каждая компактная особенность/черта требует automation.mode:
full, partial, manual или passive. partial/manual обязательно перечисляют
`automation.manual`; full требует activity или эффект, passive не допускает
нажимаемых activities. Наличие кнопки не доказывает автоматизацию всего текста.

Общий ресурс объявляется в resource_pool и расходуется через mechanics.resource
с type pool. Поддержаны операции consume, restore, clear, raise, consumeAll,
require_empty и max_cost. `runtime/resource-pools.mjs` входит в модуль.
Индивидуальные uses внутри составных activities остаются независимыми.
Эффекты вложенного шага привязываются к его ID, не к соседней кнопке.

## Сборка и проверка

```console
python character_builder.py examples/standard_options.json --output-dir output/example
python character_builder.py examples/standard_options.json --output-dir output/module --module-id example-content --cli-module /path/to/node_modules/@foundryvtt/foundryvtt-cli/index.mjs
```

Первая команда выдаёт каталог JSON и ZIP отдельных документов, вторая также
создаёт устанавливаемый `example-content-module.zip`. Нужны Python 3.10+,
а для LevelDB — Node.js и официальный Foundry CLI 3.0.5.

Перед выпуском: self-test, project_audit.py, тесты tests/, тест runtime и
настоящая сборка/обратное чтение LevelDB с FOUNDRY_CLI_MODULE.
В живом Foundry проверить новую персону, размер/владения/бонусы, выдачу по
уровням, выбор каждого подкласса, расход и восстановление, независимость двух
персонажей. Ранее импортированные документы сами не обновляются.
