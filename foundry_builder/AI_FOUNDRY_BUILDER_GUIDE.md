# Стартовое руководство ИИ для FoundryVTT Builder

Версия маршрута: 2.1

Это единственная обязательная точка входа. Определи задачу и открой только
указанные документы. Не читай весь комплект: правила разных сущностей не должны
смешиваться в одном контексте.

## 1. Маршрут работы

| Задача | Что читать и делать |
|---|---|
| Только придумать контент | `docs/CONTENT_DESIGN.md` → создать и проверить статблок; JSON не нужен |
| Преобразовать готовый контент | `docs/COMMON_JSON.md` → профильные документы → `docs/VALIDATION.md` → шаблон → фактическая сборка |
| Придумать и преобразовать | `docs/CONTENT_DESIGN.md` → внутренний полный статблок → маршрут преобразования |
| Исправить JSON или билдер | воспроизвести дефект → открыть общие и профильные правила → исправить источник → регрессионная проверка |
| Изменить проект | `docs/PROJECT_MAINTENANCE.md` → затронутые документы и код → сборка через `package_project.py` |

Готовый статблок и первичный JSON — разные артефакты. Не меняй баланс и смысл
уже утверждённого контента при преобразовании.

## 2. Профильные документы

После `docs/COMMON_JSON.md` открой только нужные файлы:

| Сущность | Документ |
|---|---|
| NPC | `docs/NPC_JSON.md`, затем документы реально присутствующих `items` |
| Оружие или оружейная атака | `docs/WEAPONS_JSON.md`, для предмета также `docs/ITEM_ENHANCEMENT_POLICY.md` |
| Заклинание | `docs/SPELLS_JSON.md` |
| Особенность, действие, реакция | `docs/FEATURES_JSON.md` |
| Доспех, щит и иная экипировка | `docs/EQUIPMENT_JSON.md` и `docs/ITEM_ENHANCEMENT_POLICY.md` |
| Расходник | `docs/CONSUMABLES_JSON.md` |
| Обычная добыча или материал | `docs/ITEMS_JSON.md` |
| Усиление или набор усилений | `docs/ENHANCEMENTS_JSON.md` |

`docs/ENHANCEMENTS_JSON.md` открывай только по явному запросу на усилитель,
усиление, набор, пул или таблицу. Наличие оружия или экипировки у NPC
не является таким запросом.

Для NPC сначала перечисли типы его `items`. Открывай их руководства в порядке:
оружие, экипировка, заклинания, особенности, расходники, добыча — пропуская
отсутствующие типы.

## 4. Обязательный процесс

1. Возьми соответствующий раздел из `templates.json`.
2. Перенеси полный игровой текст и все механические элементы исходника.
3. Заполни только входные поля: `system.activities` до сборки остаётся `{}`,
   временная механика находится в корневом `mechanics`.
4. Прогони JSON через правильный режим `builder_app.py`.
5. Исправь все ошибки и выполни смысловую сверку по
   `docs/VALIDATION.md`.
6. Передавай результат только после успешной фактической сборки.

Билдер не додумывает цели, длительность, Сл, расход ресурсов и условия
окончания. Неподдерживаемую часть сохрани точным текстом и отметь как ручную.

## 5. Правило остановки

Если руководство, шаблон и фактическое поведение билдера противоречат друг
другу, не выбирай вариант по догадке. Воспроизведи расхождение, определи
каноническое поведение и исправь затронутый слой вместе с проверкой.
