# Сопровождение проекта и канонического ZIP

## Рабочий источник

В репозитории WoWMapTools рабочие исходники находятся в `foundry_builder/`,
ветка `foundry-builder`. Изменения выполняются в checkout и фиксируются в git.
Не нужно сначала перепаковывать или распаковывать прежний Library-архив:
он остаётся снимком на момент публикации.

Если задача относится к самостоятельному ZIP вне репозитория, распакуйте его
в новую пустую папку. Корень архива — `Генератор JSON для импорта в FoundryVTT`.
Архив на месте не редактируется.

## Процесс изменения

1. Запустите `python project_audit.py` до изменения.
2. Воспроизведите проблему и измените рабочий источник.
3. При изменении контракта обновите профильное руководство, шаблон и проверку.
4. Выполните профильные проверки, `python builder_app.py --self-test`
   и `python project_audit.py`.
5. Для самостоятельной поставки выполните
   `python package_project.py --output ../output/FoundryVTT_Builder_Project.zip`.
6. Упаковщик сверяет точный состав и байты, распаковывает архив и повторяет аудит.
   Только после успеха публикуйте результат.

В репозитории запустите также общие проверки Python и документации из его корня.
Если старое руководство противоречит проверенному коду, исправьте его вместе с
регрессией, а не сохраняйте конфликт как правило работы.

## Манифест и версии

`PROJECT_MANIFEST.json` задаёт цели и разрешённый состав исходной поставки:
`canonical_files` плюс сам манифест. Пути относительные, безопасные и уникальные.
Новые постоянные файлы добавляются в манифест; удалённые и переименованные —
убираются. Логи, кэши, output, node_modules и пользовательские JSON не входят в ZIP.

`targets.foundry` — целевая версия, `targets.export_core` — нижняя совместимая
сборка той же схемы. Исходящие `_stats.coreVersion` получают `export_core`,
включая вложенные документы. `systemVersion` сохраняет точную версию dnd5e.

Канонические имена сохраняются; варианты `v2`, `final`, `fixed`, `(1)` не
создаются вместо исправления существующего исходника. Если отдельный внешний
`AI_FOUNDRY_BUILDER_GUIDE.md` публикуется вместе с ZIP, берите его из той же
проверенной рабочей копии: текст должен побайтово совпадать с экземпляром внутри архива.
Обновление GitHub само по себе не заменяет ранее опубликованные Library-файлы.

## Генерируемые модули

`python build_enhancement_module.py enhancement_test_set.json` создаёт модуль
по запросу. Сборка проверяет ZIP, module.json, три LevelDB-пака, packFolders,
контроллер, состав документов и соответствие исходникам. Нужные зависимости,
включая Foundry CLI, устанавливаются в среду сборки отдельно.
Результаты и отчёты не становятся исходниками автоматически.
