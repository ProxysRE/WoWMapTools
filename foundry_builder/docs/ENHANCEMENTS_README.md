# Система усилений

Новая система использует штатную activity D&D5e `Enchant`. Старый
`random_upgrade` и его runtime больше не требуются.

## Сборка

Откройте `start_builder_app.bat` и выберите:

- **Усиление** — полная проверка одной записи и создание элемента каталога;
- **Набор усилений** — полная проверка и сборка устанавливаемого ZIP.

Кнопка **Проверить JSON** выполняет пробную компиляцию без сохранения
результата. Перед сборкой ZIP установите официальный CLI:

```bash
npm install -g @foundryvtt/foundryvtt-cli
```

Для командной строки создайте `enhancement_set` по
`docs/ENHANCEMENTS_JSON.md` и запустите:

   ```bash
   python build_enhancement_module.py enhancement_test_set.json
   ```

Готовый ZIP появится в
`output/enhancements/foundry-json-builder-enhancements.zip`.

Если `fvtt` не находится через `PATH`, передайте
`--fvtt-cli "полный/путь/к/fvtt"`.

## Контрольный набор

`enhancement_test_set.json` создаёт:

- семь расходников: прежний общий усилитель, четыре точечных rider-теста и два
  составных усилителя;
- четырнадцать самостоятельных Enchantment-компонентов и две записи связок;
- семь настоящих RollTable `1d100`;
- Item-пак каталога;
- контроллер, заменяющий прежнее усиление той же группы и разворачивающий
  составной профиль в независимые компоненты;
- окончательный реестр из девяти групп, ранги `standard`, `exceptional`,
  `unique`, `artifact` и отдельный дополнительный слот `signature_property`,
  который содержит минимум два уникальных эффекта и не блокирует обычные
  группы;
- проверку `target.system_types`, не позволяющую наложить броневой профиль на
  кольцо, амулет или другую неподходящую экипировку;
- политику предмета `open`, `restricted` или `locked`, резервирование групп
  встроенными `native_properties` и безопасный запрет усилений для старых
  артефактов без явной политики;
- отдельный врождённый `material_property`, который хранится на самом
  предмете, не занимает слоты усилений и не может быть установлен
  Enchantment;
- автоматическое требование настройки при суммарном весе усилений `4` или
  явном `attunement.required: true`.

Четыре точечных теста проверяют:

- активную кнопку с временным эффектом на владельца;
- активную кнопку со спасброском и эффектом выбранной цели;
- постоянный переносимый эффект владельца;
- отдельную атаку с эффектом цели при попадании.

Оружейный составной тест проверяет одновременное наложение четырёх независимых
усилений:
`+2`, `2d6` огненного урона, сопротивления огню владельца и активного
15-футового конуса. Конус имеет 3 собственных заряда, расходует
`activityUses` и восстанавливает все применения после продолжительного
отдыха. Последующая замена одного компонента не должна удалять остальные три.

Составной тест экипировки проверяет применение к `equipment`: `+2` к КД через
`system.armor.magicalBonus`, сопротивление электричеству владельца и активную
10-футовую грозовую волну с 3 собственными зарядами. Его допустимые подтипы:
`light`, `medium`, `heavy`, `natural`, `shield`. Оба составных профиля
набирают вес настройки выше порога и должны автоматически установить предмету
`system.attunement: "required"`. После удаления достаточного числа компонентов
автоматическая настройка снимается, но ручное требование настройки сохраняется.

Все три пака отображаются в боковой панели внутри общего раздела
«Усиления». Технически они остаются раздельными, поскольку Item и RollTable
являются разными типами документов Foundry.

После установки ZIP включите модуль в мире D&D5e 5.3.3, перенесите усилитель
из компендиума на персонажа и выполните smoke-тест из
`docs/ENHANCEMENTS_JSON.md`.
