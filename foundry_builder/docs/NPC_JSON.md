# NPC → JSON

Правила каркаса актёра, характеристик, защит, навыков и состава `items`.
Если NPC содержит заклинания, оружие, экипировку или особенности, после этого
руководства открой соответствующие профильные документы:

- оружие и оружейные атаки — `WEAPONS_JSON.md`;
- экипировка — `EQUIPMENT_JSON.md`;
- заклинания — `SPELLS_JSON.md`;
- особенности, действия и реакции — `FEATURES_JSON.md`;
- расходники — `CONSUMABLES_JSON.md`;
- обычная добыча — `ITEMS_JSON.md`.

Открывай их в этом порядке, пропуская типы, которых у NPC нет.

## Готовая инструкция для ИИ: NPC

Преобразуй предоставленный статблок D&D 5e в первичный `npc.json` для `build_npc.py`.

Обязательные правила:

1. Верни только один корректный JSON-объект. Не используй Markdown, комментарии и пояснения вне JSON.
2. Используй секцию `templates.npc` из `templates.json`.
3. Не придумывай отсутствующие в статблоке свойства.
4. Сохраняй полный текст каждой особенности и атаки в `system.description.value`.
5. В корне должны быть `name`, `type`, `img`, `system`, `prototypeToken`,
   `items`, `effects`, `folder`, `flags`, `_stats`. Служебный `_stats` бери
   из `templates.npc` без изменений: отсутствие версии системы может
   вызвать ошибочную миграцию при импорте и сбросить уровень заклинателя.
6. Корневой `type` всегда равен `"npc"`.
7. В `items`:
   - заклинание из списка заклинаний НПС создавай как `"type": "spell"`;
   - врождённое действие с броском атаки, которое не является отдельным заклинанием, создавай как `"type": "weapon"`;
   - доспех, щит, кольцо, одежду, жезл и другой носимый предмет создавай как
     `"type": "equipment"`;
   - зелье, яд, пищу, свиток и другой одноразовый предмет создавай как
     `"type": "consumable"`;
   - драгоценность, материал, сокровище и обычную добычу без механики создавай
     как `"type": "loot"`;
   - пассивные черты, мультиатаку, спасброски, лечение, реакции, бонусные, легендарные действия и действия логова создавай как `"type": "feat"`;
   - не создавай изображения и поле `img`;
   - перед сборкой `system.activities` всегда должен быть пустым объектом `{}`;
   - временную разметку для билдера помещай в корневое поле предмета `mechanics`.
8. Если одна способность содержит несколько раздельно нажимаемых частей, перечисли их в `mechanics.activities`.
9. Автоматизируй только поддерживаемые броски: атака, урон, спасбросок, лечение, временные хиты, дополнительный произвольный бросок и расход использований. Урон без броска атаки и без спасброска всегда размечай как `damage`, а не как `utility`.
10. Для заклинаний, особенностей и оружия разрешено создавать поддерживаемые Active Effects: стандартные состояния и изменения системных полей через `changes`. Телепортацию, принудительное перемещение, изменение максимума хитов, запрет лечения, превращение, призыв и условное падение до 0 хитов сохраняй полным текстом.
11. Формулы записывай без среднего значения: `"2d8+6"`, а не `"15 (2d8 + 6)"`.
12. Используй только английские системные идентификаторы, перечисленные ниже.
13. Не копируй в итоговый JSON примеры, которых нет в исходном статблоке.

## 1. Каркас актёра

Основные характеристики:

```text
"abilities": {
  "str": {"value": 18, "proficient": 1, "bonuses": {"check": "", "save": "+1", "skill": ""}},
  "dex": {"value": 16, "proficient": 0, "bonuses": {"check": "", "save": "", "skill": ""}},
  "con": {"value": 20, "proficient": 1, "bonuses": {"check": "", "save": "+1", "skill": ""}},
  "int": {"value": 14, "proficient": 0, "bonuses": {"check": "", "save": "", "skill": ""}},
  "wis": {"value": 18, "proficient": 1, "bonuses": {"check": "", "save": "+1", "skill": ""}},
  "cha": {"value": 20, "proficient": 1, "bonuses": {"check": "", "save": "+1", "skill": ""}}
}
```

`proficient`:

- `0` — нет владения;
- `1` — владение;
- `2` — двойное владение, если система это допускает.

Для точного спасброска:

```text
итог = модификатор характеристики + proficient × бонус мастерства + bonuses.save
```

Пример: Сила 18, бонус мастерства +6, спасбросок Силы +11:

```json
{"value": 18, "proficient": 1, "bonuses": {"check": "", "save": "+1", "skill": ""}}
```

Если итог уже получается без поправки, `bonuses.save` должен быть `""`.

КД:

```text
"ac": {"calc": "flat", "flat": 19, "formula": ""}
```

- Для указанного в статблоке итогового значения используй `"calc": "flat"`.
- Для формулы используй `"calc": "formula"`, `"flat": null` и заполни `formula`.
- Не пытайся создавать доспех через `actor_builder.py`.
- Если эффект должен временно изменять КД актёра с `"calc": "flat"`, меняй
  `system.attributes.ac.flat`. Ключ `system.attributes.ac.bonus` с неизменной
  КД не работает и будет отклонён валидатором. Используй `ac.bonus` только с
  совместимым способом расчёта КД.

Хиты:

```text
"hp": {
  "value": 285,
  "max": 285,
  "temp": 0,
  "tempmax": 0,
  "formula": "30d8 + 150"
}
```

Передвижение:

```text
"movement": {
  "walk": 30,
  "fly": 30,
  "swim": 0,
  "climb": 0,
  "burrow": 0,
  "units": "ft",
  "hover": true
}
```

Если скорость не указана, ставь `0`. `hover: true` используй только при явно указанной левитации или парении.

Чувства:

```text
"senses": {
  "ranges": {
    "darkvision": null,
    "blindsight": null,
    "tremorsense": null,
    "truesight": 60
  },
  "units": "ft",
  "special": ""
}
```

Неизвестное особое чувство записывай текстом в `special`.

Размеры:

| Статблок | Код |
|---|---|
| Крошечный | `tiny` |
| Маленький | `sm` |
| Средний | `med` |
| Большой | `lg` |
| Огромный | `huge` |
| Громадный | `grg` |

Типы существ:

`aberration`, `beast`, `celestial`, `construct`, `dragon`, `elemental`, `fey`, `fiend`, `giant`, `humanoid`, `monstrosity`, `ooze`, `plant`, `undead`.

Необычное уточнение записывай в `system.details.type.custom`.

## 2. Сопротивления, иммунитеты и языки

```text
"traits": {
  "size": "med",
  "di": {"value": ["poison"], "custom": ""},
  "dr": {"value": ["cold", "fire", "necrotic"], "custom": "Дробящий, колющий и рубящий урон от немагических атак"},
  "dv": {"value": [], "custom": ""},
  "ci": {"value": ["poisoned", "frightened", "exhaustion"], "custom": ""},
  "languages": {
    "value": ["common", "infernal"],
    "custom": "",
    "communication": {
      "telepathy": {"value": 120, "units": "ft"}
    }
  }
}
```

Типы урона:

`acid`, `bludgeoning`, `cold`, `fire`, `force`, `lightning`, `necrotic`, `piercing`, `poison`, `psychic`, `radiant`, `slashing`, `thunder`.

Состояния:

`blinded`, `charmed`, `deafened`, `exhaustion`, `frightened`, `grappled`, `incapacitated`, `invisible`, `paralyzed`, `petrified`, `poisoned`, `prone`, `restrained`, `stunned`, `unconscious`.

Условные сопротивления, например «от немагических атак», записывай в `custom`, а не превращай в безусловный иммунитет.

## 3. Навыки

В `system.skills` добавляй только навыки, перечисленные в статблоке.

```text
"skills": {
  "prc": {
    "value": 1,
    "ability": "wis",
    "bonuses": {"check": "+1", "passive": ""}
  }
}
```

`value`: `0` — нет владения, `1` — владение, `2` — экспертиза.

```text
итог навыка = модификатор характеристики + value × бонус мастерства + bonuses.check
```

Коды распространённых навыков:

| Навык | Код | Характеристика |
|---|---|---|
| Акробатика | `acr` | `dex` |
| Анализ | `inv` | `int` |
| Атлетика | `ath` | `str` |
| Восприятие | `prc` | `wis` |
| Выживание | `sur` | `wis` |
| Выступление | `prf` | `cha` |
| Запугивание | `itm` | `cha` |
| История | `his` | `int` |
| Ловкость рук | `slt` | `dex` |
| Магия | `arc` | `int` |
| Медицина | `med` | `wis` |
| Обман | `dec` | `cha` |
| Природа | `nat` | `int` |
| Проницательность | `ins` | `wis` |
| Религия | `rel` | `int` |
| Скрытность | `ste` | `dex` |
| Убеждение | `per` | `cha` |
| Уход за животными | `ani` | `wis` |

Пассивное Восприятие обычно рассчитывается автоматически. Если указанное значение отличается, разницу внеси в `bonuses.passive`.
