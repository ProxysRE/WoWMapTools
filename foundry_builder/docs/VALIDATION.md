# Финальная проверка JSON

Этот документ не повторяет профильные правила. Он проверяет две вещи:
техническую сборку и совпадение результата с исходным замыслом.

## 1. Фактическая сборка

Перед выдачей JSON пользователю в чате:

1. Запусти файл через правильный режим `builder_app.py`.
2. Исправь все `source_contract.errors`.
3. Убедись, что `midi_compatibility.errors` пуст.
4. Если изменялся проект, дополнительно выполни `--self-test` и
   `project_audit.py`.
5. Не передавай результат, который не собрался или был исправлен вручную уже
   после сборки.

## 2. Смысловая сверка

Автоматический валидатор не знает исходный замысел. Составь внутренний перечень
всех заголовков, пассивов, атак, кнопок, ресурсов и числовых механик исходника.
Для каждого пункта проверь:

- полное правило присутствует в `system.description.value`;
- поддерживаемая механика имеет activity или Active Effect;
- ручная часть сохранена точным текстом;
- формулы, Сл, цели, длительность и расходы совпадают с исходником;
- ни одна способность не добавлена по догадке и не пропущена.

## 3. Критические проверки результата

- Тип корня и режим билдера соответствуют сущности.
- Вход создан из правильной секции `templates.json`; до сборки
  `system.activities` был пуст.
- Каждая attack-activity имеет эффективный урон. Первый компонент обычной
  атаки оружия полностью совпадает с `system.damage.base`, включая фиксированный
  модификатор: `1d8+7` не может превратиться в `1d8`.
- `system.magicalBonus` оружия и `system.armor.magicalBonus` брони не
  продублированы в формулах или эффектах.
- Каждый спасбросок содержит характеристику и Сл; пустой спасбросок имеет
  связанный эффект либо точное ручное последствие.
- Каждый Active Effect существует в корневом `effects` готового Item и связан
  с правильной activity. Эффект владельца использует `transfer: true`, цели —
  `transfer: false`.
- Общий ресурс, заряд или ячейка списывается ровно одной фактической кнопкой.
- Условный или отложенный урон не встроен в activity, при которой он не должен
  срабатывать.
- При неизменной КД (`calc: "flat"`) эффект меняет `ac.flat`, а не `ac.bonus`.
- Площадная механика имеет форму, размер, единицы, корректный выбор целей и
  подтверждение Midi-QOL.
- У NPC-заклинателя присутствуют характеристика, уровень и ячейки.
- Новое оружие и экипировка имеют `enhancement_policy`, соответствующую
  `ITEM_ENHANCEMENT_POLICY.md`. Для `locked` полная классификация врождённых
  свойств не требуется; `material_property` заполнено только при явном
  особом материале.

Успешная сборка подтверждает структуру, но не заменяет эту смысловую сверку.
