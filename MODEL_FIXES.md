# Исправления мурлока и кобольда

## Кобольд: неиспользуемая ссылка не является зависимостью рендера

У `creature/kobold/kobold.m2` объявлена текстура
`world/expansion02/doodads/dalaran/glowball.blp`. Однако таблица текстур выбранного
первого SKIN ссылается только на текстуру тела (тип 11), а не на glowball.
Прежняя проверка требовала все имена из заголовка, поэтому ошибочно блокировала рендер.

Теперь проверяются реальные material batches выбранного SKIN. Для рендера нужны
сама модель, первый SKIN и текстуры, на которые ссылаются эти batches. Другие LOD
и неиспользуемые имена сохраняются в диагностике, но не требуют загрузки.
Эти же правила применены к каталогу пакетов, ключу кэша объектов и хешам исходников токенов.
Кэш спрайтов получил новую версию, чтобы не переиспользовать старые результаты материалов.

`inspect_model` различает:

- `missing` — отсутствующие необходимые ресурсы выбранного SKIN;
- `declared_missing` — все отсутствующие объявления заголовка;
- `unused_missing` — объявления, которые выбранный рендер не использует;
- `inspection_complete` — удалось ли прочитать выбранный SKIN;
- `required_skins`, `required_textures`, `used_replaceable_texture_types` — реальные зависимости.

Если выбранного SKIN ещё нет, зависимости не объявляются полностью известными.
Если отсутствует **используемая** текстура, рендер по-прежнему останавливается.
Ресурсы не подменяются и не пропускаются молча. Для исправленного кобольда загрузка
общего пакета ради glowball не понадобилась.

## Мурлок: дополнительный отражающий слой

У `creature/murloc/murloc.m2` есть material pass с режимом 4 (alpha-additive),
флагом NoZWrite и сферическими координатами текстуры. Раньше режим явно отклонялся.
Теперь он отрисовывается после основного тела и непрозрачных/вырезанных деталей:

- исходный RGB умножается на альфу и добавляется к уже видимой поверхности;
- сферические UV строятся из нормалей в координатах камеры, отдельно для каждого ракурса;
- допускается совпадающая глубина поверхности и её отражающего слоя;
- учитывается заслонение телом; для слоя с NoZWrite глубина не перезаписывается;
- внутри одного слоя выбирается ближайший фрагмент, чтобы не удваивать свет на стыках;
- чёрные пиксели additive-текстуры не создают непрозрачный чёрный фон.

Опорный исходник семантики материалов:
https://github.com/wowmodelviewer/wowmodelviewer/blob/master/src/games/wow/ModelRenderPass.cpp

Прозрачный WebP/PNG не может выполнять настоящее additive-смешивание с произвольной
будущей картой Foundry. Над непрозрачным телом прибавление цвета сохраняется; вне тела
свечение сведено в обычный RGBA по приближённой альфе покрытия. Это записано в отчёте.
Сферическая карта использует ортографическую камеру. Полное освещение и шейдеры
движка WoW, анимация материалов, частицы и billboarding по-прежнему не воспроизводятся.
Режимы 3, 5 и другие неподдержанные варианты явно отклоняются, а не заменяются режимом 4.
Старый режим 2 пока сохраняет отсечение альфы: исправление не заявляет полный новый рендерер.

## Проверка на реальных данных

Проверены мурлок display ID **188** и кобольд **26**, каждый сверху и анфас.
Готовый тестовый пакет строится командой:

```console
python tools/build_foundry_batch.py requests/builder/material-fixes.json --dbc-assets "D:\WoWAssets\DBC" --model-assets "D:\WoWAssets\Models" --out output/material-fixes
```

Папка моделей должна содержать соответствующие ZIP из приватной выгрузки.
В пакете два технических NPC, четыре изображения и отчёты. Боевые характеристики
не проектировались: характеристики 10, КД 10, 1 хит, скорость 0, CR 0, без действий.
Для проверки в Foundry скопируйте только папку `wowmap` в пользовательскую Data,
импортируйте JSON в новых NPC и сравните портреты с токенами на любой сцене.
Позы остаются исходными: по просьбе пользователя работа над ними отложена.

## Дополнительное исправление нативной проверки

При прогоне полного набора с StormLib на Linux обнаружилось повреждение памяти
при перечислении MPQ. В `SFILE_FIND_DATA` длина имени была ошибочно задана как 260
байт для всех платформ, хотя закреплённый StormLib 9.40 использует 1024 вне Windows.
Размер структуры ctypes теперь соответствует платформе; Windows сохраняет 260.
Добавлена проверка защитных байтов вокруг структуры при реальном перечислении MPQ.
Это отдельный дефект чтения архивов, а не проблема геометрии мурлока или кобольда.
