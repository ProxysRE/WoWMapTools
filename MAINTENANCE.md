# Сопровождение WoWMapTools и Builder

Разработка интеграции ведётся в git, ветка **foundry-builder**. Исходная Library-копия
Builder — прежний снимок, а не обязательный промежуточный этап каждой правки.
Ресурсы клиента, сборки и кэши не коммитятся.

## Проверка изменений

Из корня:

```console
python tools/check_docs.py
python -m unittest discover -s tests -q
```

Проверяются локальные inline Markdown-ссылки на файлы и каталоги, но не внешние сайты,
фрагменты-заголовки и смысл текста. Python-набор запускает проверку JS-импортёра
с имитацией API, если доступен Node. Нативные MPQ-тесты требуют StormLib; без неё
пропускаются. Не называйте такой запуск полной проверкой MPQ.
CI `Windows packer` выполняет их с библиотекой на Windows и Linux.

После правки `foundry_builder/` дополнительно:

```console
cd foundry_builder
python builder_app.py --self-test
python project_audit.py
python package_project.py --output ../output/FoundryVTT_Builder_Project.zip
```

Упаковщик сверяет состав и байты, распаковывает ZIP и повторяет аудит.
Контракт задают код и `PROJECT_MANIFEST.json`; руководства обновляются
вместе с поведением. Исходник `mechanics` не выдаётся за готовый JSON Foundry.

В Actions: `Checks` проверяет Python и документацию, `Windows packer` — MPQ и
Windows-пакет, `Foundry JSON Builder` — самостоятельный Builder и активное задание.
Hosted runners не получают приватные ресурсы из чата.
Игровая проверка указывается отдельно от имитации API и локального рендера.

## Кэши ресурсов

`RawAssets` держит ZIP открытыми на время операции. CRC проверяется при первом
чтении выбранного файла. Повторные чтения используют LRU-кэш: до **16 MiB /
128 записей** исходных байтов и **32 MiB / 32 записей** RGBA-текстур.
Большие отдельные записи не удерживаются в соответствующем кэше.
Это ограничения кэшей, а не общей памяти: геометрия, карта и готовые изображения
занимают память отдельно. Не меняйте пакеты во время сборки.

Пакетный Builder использует одну ленивую сессию моделей для всех NPC и ракурсов.
Она закрывается при успехе и исключении. Одиночные `select` и `pair` сохраняют
самостоятельное управление ресурсами. Дисковый кэш спрайтов карт сохраняется.

Для собранного персонажа токен и портрет используют один атлас, один набор
геометрии и один список SHA-256 источников. Хранится только текущий костюм,
только до закрытия сессии; новый костюм заменяет предыдущий. Повороты камеры
применяются к копии вершин, поэтому ракурсы не влияют друг на друга. Отчёты
возвращаются отдельными копиями. При исключении кэш также освобождается.

Индексирование виртуальных путей не создаёт объект pathlib для каждого файла.
Проверки абсолютных путей, `..` и `:` сохранены; эквивалентность прежним правилам
проверена на 16 807 комбинациях. Изменение действует на общую упаковку ресурсов,
модели, иконки и карты. Оно не вводит глобального кэша индексов архивов.

Оптимизация не меняет материалы, позы, разрешение или алгоритм отрисовки.
Сравниваются готовые файлы и число чтений; длительность зависит от среды.

## Индекс архивов

Опциональный `asset-index.sqlite` создаётся командой
`python -m wowmap.asset_index --packages <folder>`. Он хранит только имена ZIP,
членов архивов, размеры и времена модификации. Сами игровые файлы не копируются.
`RawAssets` сверяет набор ZIP и их метаданные, затем открывает только используемые
архивы. Устаревший или повреждённый индекс игнорируется: выполняется обычный поиск.
`verify_archives=True` всегда обходит индекс и проверяет ZIP полностью.
Индекс можно удалить и воспроизвести; менять ZIP во время сборки по-прежнему нельзя.

Растеризатор получает текстуры один раз на пакет рисования, а не для каждого
треугольника; полностью закрытые фрагменты пропускаются до выборки текстур.
В трёх чередующихся локальных прогонах пяти настоящих NPC крипты (10 ракурсов
512/640 px) медиана уменьшилась с 5,823 до 4,702 с, примерно на 19,3%.
Все 21 изображение полного DEV2-R4 дополнительно пересчитаны и совпали побайтно.
Позы, материалы и разрешение не менялись. Это локальные измерения, не гарантия
фиксированного ускорения любого проекта.

Наручи voidwalker.m2 не исправлялись: скрытые части используют нулевые дорожки
прозрачности материала, пока не применяемые рендерером. Скелетная поза сама по
себе их не скрывает. Текущее назначение idle/bind в запросе крипты также сохранено.


### Обязательные изображения NPC при выпуске

Все новые пакеты NPC должны задавать `require_item_icons: true` и
`require_explicit_angles: true` в запросе batch. Для каждого встроенного
предмета/особенности/атаки указывается точное соответствие `item_icons` по
`system.identifier`. Иконка выбирается из выгруженного WoW Interface/Icons,
проверяется по исходному SHA-256 и включается в поставку. Пустая иконка или
стандартный меч — ошибка приёмки, включая кнопки activities. Проверка иконок включена по умолчанию. Старые демонстрационные
запросы явно помечены `require_item_icons: false` как изолированные проверки
сборщика; они не являются шаблоном выпуска.

Для каждого appearance явно задаются `yaw` и `portrait_yaw`; результаты проверяются
на контактном листе. Универсальный портрет в анфас не принимается автоматически.
Для вытянутой фауны сначала сравнить варианты 25/40/55/70 градусов. Ракурсы крипты
и все 66 привязок воспроизводятся `tools/prepare_crypt_population.py`. Финальный
`verify_delivery_document` независимо отклоняет крипту с пустыми иконками.
Для уже импортированной R4 используется `UPDATE_EXISTING_RU.js`: изменения только
изображений, без пересоздания NPC/сцен и сброса состояния боя.


### Направление токенов и порядок этапов (уточнение 28.10.2026)

Художественные углы подбираются только портретам. Токен остаётся сверху с базовым
направлением текущего рендерера `yaw: -90`; вращением управляет Foundry. R4.1
с известным диагональным отклонением остаётся без пересборки по решению пользователя.
Новые варианты внешности используют базовое направление и явную боевую позу.
Сначала завершаются все карты, по одной сцене за проход. Затем создаются обитатели,
также полный набор для одной сцены за проход. Дробить знакомые работы до одного
моба или одной способности не требуется. Непроверенную новую технологию сначала
проверять на небольшом законченном примере. См. [варианты внешности](CHARACTER_VARIANTS.md).
