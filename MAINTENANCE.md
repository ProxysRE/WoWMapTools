# Сопровождение WoWMapTools и Builder

Разработка интеграции ведётся в git, ветка **foundry-builder**. Исходная Library-копия
Builder — прежний снимок, а не обязательный промежуточный этап каждой правки.
Ресурсы клиента, сборки и кэши не коммитятся.

## Проверка изменений

Из корня:

```console
python tools/check_docs.py
python -m unittest discover -s tests -q
```

Проверяются локальные inline Markdown-ссылки на файлы и каталоги, но не внешние сайты,
фрагменты-заголовки и смысл текста. Python-набор запускает проверку JS-импортёра
с имитацией API, если доступен Node. Нативные MPQ-тесты требуют StormLib; без неё
пропускаются. Не называйте такой запуск полной проверкой MPQ.
CI `Windows packer` выполняет их с библиотекой на Windows и Linux.

После правки `foundry_builder/` дополнительно:

```console
cd foundry_builder
python builder_app.py --self-test
python project_audit.py
python package_project.py --output ../output/FoundryVTT_Builder_Project.zip
```

Упаковщик сверяет состав и байты, распаковывает ZIP и повторяет аудит.
Контракт задают код и `PROJECT_MANIFEST.json`; руководства обновляются
вместе с поведением. Исходник `mechanics` не выдаётся за готовый JSON Foundry.

В Actions: `Checks` проверяет Python и документацию, `Windows packer` — MPQ и
Windows-пакет, `Foundry JSON Builder` — самостоятельный Builder и активное задание.
Hosted runners не получают приватные ресурсы из чата.
Игровая проверка указывается отдельно от имитации API и локального рендера.

## Кэши ресурсов

`RawAssets` держит ZIP открытыми на время операции. CRC проверяется при первом
чтении выбранного файла. Повторные чтения используют LRU-кэш: до **16 MiB /
128 записей** исходных байтов и **32 MiB / 32 записей** RGBA-текстур.
Большие отдельные записи не удерживаются в соответствующем кэше.
Это ограничения кэшей, а не общей памяти: геометрия, карта и готовые изображения
занимают память отдельно. Не меняйте пакеты во время сборки.

Пакетный Builder использует одну ленивую сессию моделей для всех NPC и ракурсов.
Она закрывается при успехе и исключении. Одиночные `select` и `pair` сохраняют
самостоятельное управление ресурсами. Дисковый кэш спрайтов карт сохраняется.

Оптимизация не меняет материалы, позы, разрешение или алгоритм отрисовки.
Сравниваются готовые файлы и число чтений; длительность зависит от среды.

### Контрольный замер

Сравнение с коммитом `c4086b2` на `requests/builder/forest-npcs.json`: три NPC,
шесть ракурсов, одинаковые приватные выгрузки и версии библиотек. Считаются
открытия ZIP графики/DBC и чтения их ресурсов; иконки в эти счётчики не входят.

| Показатель | До | После |
|---|---:|---:|
| Открытия ZIP | 40 | 10 |
| Чтения ресурсов ZIP | 66 | 12 |
| Прочитанные байты | 11 427 839 | 3 104 999 |
| Время одного прогона, с | 6.395 | 4.806 |

Все 24 выходных файла совпали побайтно, включая JSON, отчёты и изображения.
Это проверка одного набора в одной среде, не обещание фиксированного ускорения
любой карты. Размер набора и число ZIP влияют на выигрыш.
